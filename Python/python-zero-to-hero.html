What is Python?

foundation · orientation

Python is a high-level, interpreted programming language. "High-level" means you write code close to human language rather than machine instructions. "Interpreted" means your code runs line-by-line through a program called the interpreter, instead of being compiled into a separate executable first.

Mental model — Compiled languages (like C) translate your whole program into machine code before running it — like translating a full book before anyone reads it. Python translates and executes one line at a time — like a live interpreter at a conference, translating sentence by sentence as the speaker talks.
Practical use — Python trades some raw execution speed for massive gains in development speed and readability. This is exactly why it dominates in scripting, automation, security tooling, and AI/data work — domains where iteration speed and clarity matter more than raw performance.

Python vs other languages

foundation · orientation

Compared to C/C++, Python is slower but dramatically faster to write and debug. Compared to JavaScript, Python has cleaner syntax for general-purpose scripting and stronger data/scientific libraries. Compared to Java, Python has far less boilerplate — no mandatory class wrappers, no explicit type declarations required.

Practical use — Choose Python when you need to move fast, glue systems together, process data, or write tools rather than ship a high-throughput production binary. It is the default language for automation scripts, security tooling, and data/AI prototyping across the industry.

Installing Python

foundation · setup

Download Python from the official source (python.org) or via your OS package manager. On installation, make sure "Add Python to PATH" is checked (Windows) so you can run python from any terminal.

Syntax
python 
# verify installation in your terminal
python3 --version
# or on some systems:
python --version
Expected output
output 
Python 3.12.x
Common mistake — Having multiple Python versions installed and not knowing which one your terminal is pointing to. Always verify with --version before starting a project, and use python3 explicitly on macOS/Linux since python may point to an old Python 2 install or nothing at all.
Practical use — A correctly configured interpreter is the foundation of every script, tool, and automation you will build — including every devforge-style CLI tool.

The Python interpreter

foundation · setup

The interpreter is the program that reads and executes your Python code. Running python3 with no arguments drops you into an interactive interpreter session (the REPL — Read, Eval, Print, Loop) where you can type code and see results immediately.

Mental model — Think of the REPL as a scratchpad for testing single ideas fast, before committing them to a real script file.
Syntax
python 
python3
>>> 2 + 2
4
>>> exit()
Practical use — Use the REPL to quickly test how a function behaves, check a data type, or verify syntax before writing it into a larger script.

Running Python code: scripts vs interactive mode

foundation · setup

A script is a .py file containing code you run all at once from top to bottom. Interactive mode (the REPL) runs code one expression at a time and keeps state between them. Real projects are built as scripts; the REPL is for quick experiments.

Syntax
python 
# save as hello.py, then run:
python3 hello.py
Example
python 
print("Hello from a script")
Expected output
output 
Hello from a script
Common mistake — Forgetting to save the file before running it, or running the wrong filename. Always double-check the file path matches what you pass to python3.
Practical use — Every real tool you build — a port scanner, a file encryptor, a CLI utility — is a script, not a REPL session.

Variables

foundation · variables

A variable is a name bound to a value stored in memory. Python variables are dynamically typed — you don't declare a type up front; the type is inferred from the value you assign.

Mental model — A variable is a labeled sticky note pointing at a value. The label can be moved to point at a different value at any time — it doesn't "contain" the value so much as reference it.
Syntax
python 
variable_name = value
Example
python 
username = "raven"
attempts = 3
is_locked = False
print(username, attempts, is_locked)
Expected output
output 
raven 3 False
Common mistake — Using invalid names — variable names cannot start with a digit, contain spaces, or use reserved keywords like class or for. 2fast = True raises a SyntaxError.
Practical use — Variables hold anything your program needs to track: user input, loop counters, configuration values, parsed data.

Core data types

foundation · data types

Python has several built-in primitive types: int (whole numbers), float (decimal numbers), str (text), bool (True/False), and None (absence of a value). Use type() to check any value's type at runtime.

Syntax
python 
type(value)
Example
python 
print(type(42))
print(type(3.14))
print(type("hello"))
print(type(True))
print(type(None))
Expected output
output 
<class 'int'>
<class 'float'>
<class 'str'>
<class 'bool'>
<class 'NoneType'>
Common mistake — Assuming "5" == 5 is True. A string and an integer are never equal in Python, even if they "look" the same — comparing them returns False, not an error.
Practical use — Knowing a value's type tells you what operations are valid on it — you can't index an int, and you can't add a string directly to a number.

None: the absence of a value

foundation · data types

None is Python's explicit representation of "no value." It is not zero, not an empty string, and not False — it is its own distinct type, used to signal that a variable has no meaningful value yet.

Example
python 
result = None
if result is None:
    print("No result yet")
Expected output
output 
No result yet
Common mistake — Comparing to None with == instead of is. Convention (and correctness with custom objects) requires is None / is not None.
Practical use — Functions that don't explicitly return anything implicitly return None — useful for representing "not found" or "not yet computed" states.

Type conversion

foundation · data types

Convert between types explicitly using int(), float(), str(), and bool(). This is essential because data from user input or files always arrives as strings.

Syntax
python 
int("42")
float("3.14")
str(100)
Example
python 
age_input = "25"
age = int(age_input)
print(age + 5)
Expected output
output 
30
Common mistake — Calling int() on a non-numeric string, like int("abc"), raises a ValueError. Always validate or wrap conversions in a try/except when the input isn't guaranteed clean (covered in Level 03).
Practical use — Every time you read user input with input(), you get a string back — conversion is required before doing any math with it.

Arithmetic operators

foundation · operators

Python supports the standard arithmetic operators: + - * /, plus // (floor/integer division), % (modulo/remainder), and ** (exponentiation).

Example
python 
print(7 / 2)
print(7 // 2)
print(7 % 2)
print(2 ** 8)
Expected output
output 
3.5
3
1
256
Common mistake — Confusing / (always returns a float) with // (floor division, returns an int when both operands are int). 7 / 2 is 3.5, not 3.
Practical use — Modulo (%) is the standard way to check divisibility — e.g. n % 2 == 0 tests for an even number, a pattern used constantly in loops and validation.

Comparison operators

foundation · operators

Comparison operators evaluate to a boolean: == != > < >= <=.

Example
python 
print(5 == 5)
print(5 != 3)
print(10 > 20)
Expected output
output 
True
True
False
Common mistake — Using a single = (assignment) where you meant == (comparison). if x = 5: is a SyntaxError in Python — the language protects you here, unlike C.
Practical use — Comparisons drive every conditional and loop condition you'll write starting in Level 02.

Logical operators

foundation · operators

Combine boolean expressions using and, or, and not. Python uses the actual words, not symbols like &&/|| in C-like languages.

Example
python 
age = 25
has_id = True
print(age >= 18 and has_id)
print(not has_id)
Expected output
output 
True
False
Common mistake — Assuming and/or always return True/False. In Python they actually return one of the operands (short-circuit evaluation) — 0 or "default" returns "default", not True.
Practical use — Combined conditions are the backbone of validation logic — e.g. checking a password meets multiple requirements at once.

Assignment operators

foundation · operators

Shorthand operators combine an operation with assignment: += -= *= /= etc. x += 1 is equivalent to x = x + 1.

Example
python 
score = 10
score += 5
print(score)
Expected output
output 
15
Practical use — Extremely common in loops — incrementing counters, accumulating totals, building up strings.

print() and input()

foundation · input & output

print() writes text to the terminal. input() pauses execution and waits for the user to type something, always returning a string.

Syntax
python 
print(value1, value2, ...)
variable = input("prompt text: ")
Example
python 
name = input("Enter your name: ")
print("Hello,", name)
Expected output
output 
Enter your name: Rwin
Hello, Rwin
Common mistake — Forgetting that input() always returns a str, even if the user types a number. input("Age: ") + 1 raises a TypeError until you convert it with int().
Practical use — These two functions are the simplest possible interface between your program and a human user — the starting point for every CLI tool.

Comments

foundation · syntax

A # starts a comment; everything after it on that line is ignored by the interpreter. Use comments to explain why, not what — the code itself should already show what it does.

Example
python 
# Convert user input to an integer before comparing
age = int(input("Age: "))
Common mistake — Over-commenting obvious code, like # add 1 to x above x += 1. This adds noise without adding understanding.
Practical use — Good comments explain non-obvious decisions, edge cases, or warnings for future readers (including future you).

Basic string manipulation

foundation · strings

Strings support concatenation with +, repetition with *, and a large set of built-in methods for transforming text.

Example
python 
greeting = "hello" + " " + "world"
print(greeting.upper())
print(greeting.replace("world", "python"))
print("-" * 10)
Expected output
output 
HELLO WORLD
hello python
----------
Common mistake — Trying to concatenate a string and a number directly: "Age: " + 25 raises a TypeError. You must convert first: "Age: " + str(25).
Practical use — String manipulation is central to parsing logs, formatting output, and cleaning user or file input.

f-strings

foundation · strings

f-strings (formatted string literals) let you embed expressions directly inside a string using {}, prefixed with f. This is the modern, preferred way to build strings from variables.

Syntax
python 
f"text {expression} more text"
Example
python 
name = "Rwin"
level = 5
print(f"{name} is at level {level}, next in {10 - level} steps")
Expected output
output 
Rwin is at level 5, next in 5 steps
Common mistake — Forgetting the f prefix — "{name}" without it prints the literal text {name} instead of the variable's value.
Practical use — f-strings are used everywhere: log messages, CLI output, generated reports — anywhere text and data mix.

Indexing and slicing

foundation · strings

Strings (and later, lists) are ordered sequences. Access a single character with [index] (0-based). Extract a range with slicing: [start:stop], where stop is exclusive.

Mental model — Think of indices as pointing to the gaps between characters, not the characters themselves — [0:3] means "everything between gap 0 and gap 3."
Example
python 
word = "python"
print(word[0])
print(word[-1])
print(word[0:3])
print(word[::-1])
Expected output
output 
p
n
pyt
nohtyp
Common mistake — Off-by-one errors — assuming word[0:3] includes index 3. It does not; slicing stops before the stop index.
Practical use — Slicing is used constantly to parse fixed-format strings, trim data, or reverse sequences.

Reading basic error messages

foundation · debugging

Python errors (exceptions) show a traceback: the file and line where the error occurred, and an error type with a message at the bottom. Read the bottom line first — it names the actual problem.

Example
python 
age = int("twenty")
Expected output
output 
Traceback (most recent call last):
  File "script.py", line 1, in <module>
    age = int("twenty")
ValueError: invalid literal for int() with base 10: 'twenty'
Common mistake — Panicking at the wall of text instead of reading the last line. ValueError, TypeError, and NameError are the most common beginner errors and each tells you exactly what went wrong.
Practical use — Fluent error-reading is the single fastest debugging skill you can build — it turns a scary wall of red text into a direct pointer to the bug.

if, elif, else

core · control flow

Conditional branching runs different code depending on whether an expression is truthy. Python uses indentation (not braces) to define code blocks — this is not a style choice, it is syntax.

Mental model — Think of indentation as physically nesting instructions inside a condition, the way an outline nests sub-points under a heading.
Syntax
python 
if condition:
    ...
elif other_condition:
    ...
else:
    ...
Example
python 
score = 72
if score >= 90:
    print("A")
elif score >= 70:
    print("B")
else:
    print("C")
Expected output
output 
B
Common mistake — Mixing tabs and spaces for indentation causes an IndentationError. Configure your editor to insert spaces only (4 spaces is the PEP 8 standard).
Practical use — Conditionals gate every meaningful decision a program makes — validating input, branching on a command, checking a scan result.

for loops

core · control flow

A for loop iterates over any iterable — a string, list, range, file, etc. — executing the block once per item.

Syntax
python 
for item in iterable:
    ...
Example
python 
for i in range(3):
    print(f"iteration {i}")
Expected output
output 
iteration 0
iteration 1
iteration 2
Common mistake — Assuming range(3) includes 3. It produces 0, 1, 2 — stop is exclusive, same rule as slicing.
Practical use — Iterating over lines in a log file, items in an API response, or entries in a wordlist is one of the most common patterns in any script.

while loops

core · control flow

A while loop repeats as long as a condition stays true. Unlike for, it doesn't iterate a fixed collection — you control the exit condition yourself.

Syntax
python 
while condition:
    ...
Example
python 
attempts = 0
while attempts < 3:
    print(f"attempt {attempts + 1}")
    attempts += 1
Expected output
output 
attempt 1
attempt 2
attempt 3
Common mistake — Forgetting to update the loop variable, causing an infinite loop. If attempts += 1 were removed above, the loop would never terminate.
Practical use — Ideal for retry logic, polling a resource until ready, or running until a user explicitly quits.

break, continue, pass

core · control flow

break exits a loop immediately. continue skips to the next iteration. pass is a no-op placeholder used where syntax requires a statement but you have nothing to do yet.

Example
python 
for n in range(10):
    if n == 3:
        continue
    if n == 6:
        break
    print(n)
Expected output
output 
0
1
2
4
5
Common mistake — Using pass when you meant continue. pass does not skip the rest of the loop body — it just does nothing at that point and execution continues normally.
Practical use — pass is common while stubbing out functions or classes during early design, before implementation is filled in.

Lists

core · collections

A list is an ordered, mutable (changeable) collection. Lists can hold mixed types and grow or shrink at runtime.

Syntax
python 
my_list = [item1, item2, item3]
Example
python 
tools = ["nmap", "wireshark"]
tools.append("burp")
tools[0] = "nmap7"
print(tools)
Expected output
output 
['nmap7', 'wireshark', 'burp']
Common mistake — Modifying a list while iterating over it directly — this silently skips elements. Iterate over a copy (for x in list[:]:) if you need to remove items during the loop.
Practical use — Lists are the default structure for any ordered, growable collection — scan results, queued tasks, parsed lines.

List methods

core · collections

Common list methods: append() adds one item, extend() merges another iterable, pop() removes and returns by index, sort() orders in place, index() finds a value's position.

Example
python 
nums = [5, 2, 8, 1]
nums.sort()
print(nums)
print(nums.pop())
Expected output
output 
[1, 2, 5, 8]
8
Common mistake — Confusing sort() (in-place, returns None) with sorted() (returns a new list). x = nums.sort() sets x to None, not the sorted list.
Practical use — sort() with a key= function is the standard way to rank results — e.g. sorting scan results by response time.

Tuples

core · collections

A tuple is an ordered, immutable collection — once created, it cannot be changed. Use tuples for fixed groupings of values that shouldn't be altered.

Syntax
python 
my_tuple = (item1, item2)
Example
python 
coordinates = (40.7128, -74.0060)
lat, lon = coordinates
print(lat, lon)
Expected output
output 
40.7128 -74.006
Common mistake — Trying to mutate a tuple: coordinates[0] = 41 raises a TypeError. If you need mutability, use a list instead.
Practical use — Tuples are ideal for fixed records — a coordinate pair, an RGB color, a function returning multiple related values.

Sets

core · collections

A set is an unordered collection of unique values — duplicates are automatically discarded. Sets support fast membership testing and mathematical operations like union and intersection.

Syntax
python 
my_set = {item1, item2}
Example
python 
seen_ips = {"10.0.0.1", "10.0.0.2", "10.0.0.1"}
print(seen_ips)
print("10.0.0.1" in seen_ips)
Expected output
output 
{'10.0.0.1', '10.0.0.2'}
True
Common mistake — Creating an empty set with {} — that actually creates an empty dict. Use set() for an empty set.
Practical use — Sets are the natural structure for deduplicating scan results or checking membership against a large blocklist efficiently.

Dictionaries

core · collections

A dictionary stores key-value pairs, giving fast lookup by key instead of by position. Keys must be unique and hashable (strings, numbers, tuples).

Syntax
python 
my_dict = {"key": "value"}
Example
python 
user = {"name": "raven", "role": "admin"}
user["active"] = True
print(user["name"])
print(user)
Expected output
output 
raven
{'name': 'raven', 'role': 'admin', 'active': True}
Common mistake — Accessing a missing key with [] raises a KeyError. Use .get("key", default) when the key might not exist.
Practical use — Dictionaries model any structured record: a parsed JSON API response, a config file, a mapping of usernames to permissions.

Dictionary methods

core · collections

.keys(), .values(), and .items() give you views for iteration. .get() safely reads with a fallback default. .pop() removes a key and returns its value.

Example
python 
config = {"debug": True, "port": 8080}
for key, value in config.items():
    print(key, "=", value)
Expected output
output 
debug = True
port = 8080
Practical use — Iterating with .items() is the standard pattern for processing every entry in a config or parsed dataset.

Nested data structures

core · collections

Lists, dicts, tuples, and sets can contain each other arbitrarily — a list of dicts, a dict of lists, etc. This is how real-world structured data (like JSON) is represented in Python.

Example
python 
users = [
    {"name": "raven", "tools": ["nmap", "burp"]},
    {"name": "alex", "tools": ["wireshark"]}
]
print(users[0]["tools"][1])
Expected output
output 
burp
Common mistake — Losing track of nesting depth and using the wrong number of index/key lookups. When structures get deep, print intermediate steps to verify shape before chaining access.
Practical use — API responses and config files are almost always nested structures — this pattern is unavoidable in real-world Python.

Defining functions

core · functions

A function is a reusable, named block of code. Define one with def; call it by name with parentheses.

Syntax
python 
def function_name(parameters):
    ...
    return value
Example
python 
def greet(name):
    return f"Hello, {name}"

print(greet("Rwin"))
Expected output
output 
Hello, Rwin
Common mistake — Forgetting return and assuming print() inside a function sends the value back to the caller. Without return, a function returns None even if it prints something.
Practical use — Functions are the single most important tool for eliminating duplicated code and organizing logic into testable units.

Default and keyword arguments

core · functions

Parameters can have default values, making them optional at call time. Arguments can also be passed by keyword, in any order, for clarity.

Example
python 
def connect(host, port=443, timeout=5):
    print(f"{host}:{port} (timeout={timeout}s)")

connect("example.com")
connect("example.com", timeout=10)
Expected output
output 
example.com:443 (timeout=5s)
example.com:443 (timeout=10s)
Common mistake — Using a mutable default argument like def f(items=[]):. The same list object is reused across all calls, causing surprising shared state. Use None and create the list inside the function instead.
Practical use — Default arguments let you design flexible, backward-compatible function signatures — critical for library and tool APIs.

*args and **kwargs

core · functions

*args collects any number of extra positional arguments into a tuple. **kwargs collects extra keyword arguments into a dict. Used when a function must accept a flexible number of inputs.

Example
python 
def log(*args, **kwargs):
    print(args, kwargs)

log("start", "scan", level="info", retry=True)
Expected output
output 
('start', 'scan') {'level': 'info', 'retry': True}
Practical use — This pattern is essential for wrapper/decorator functions that must forward arbitrary arguments to another function.

Scope

core · functions

A variable defined inside a function is local — it doesn't exist outside that function. A variable defined at the top level of a script is global and readable (but not writable, by default) inside functions.

Example
python 
x = 10
def show():
    print(x)  # reads global

def change():
    x = 99  # creates a NEW local x
    print(x)

show()
change()
print(x)
Expected output
output 
10
99
10
Common mistake — Assuming assignment inside a function modifies the global variable. It creates a separate local variable instead, unless you explicitly declare global x.
Practical use — Understanding scope prevents a huge class of bugs where a function seems to "not update" a value the caller expected changed.

Lambda functions

core · functions

A lambda is a small, anonymous, single-expression function. Useful for short throwaway functions passed directly as arguments — most commonly as a key for sorting.

Syntax
python 
lambda arguments: expression
Example
python 
pairs = [(1, "b"), (2, "a")]
pairs.sort(key=lambda p: p[1])
print(pairs)
Expected output
output 
[(2, 'a'), (1, 'b')]
Common mistake — Writing complex, multi-line logic crammed into a lambda. If it needs more than one expression or a name to be readable, use a regular def function instead.
Practical use — Lambdas shine as sort keys, quick filter conditions, or simple callback functions — anywhere a full function definition would be overkill.

List and dict comprehensions

core · comprehensions

Comprehensions build a new list or dict from an iterable in a single, readable expression — a concise replacement for a manual loop with .append().

Syntax
python 
[expression for item in iterable if condition]
{key_expr: val_expr for item in iterable}
Example
python 
squares = [n**2 for n in range(6) if n % 2 == 0]
print(squares)

lengths = {word: len(word) for word in ["hi", "python"]}
print(lengths)
Expected output
output 
[0, 4, 16]
{'hi': 2, 'python': 6}
Common mistake — Nesting too many conditions or loops inside a single comprehension until it becomes unreadable. If it needs more than one for or two conditions, write it as a normal loop.
Practical use — Comprehensions are idiomatic Python — used constantly to filter and transform data in one line, especially when parsing files or API results.

Modules and imports

core · modules

A module is just a .py file. Import it to reuse its functions/classes elsewhere. Python's standard library ships dozens of built-in modules ready to import.

Syntax
python 
import module_name
from module_name import specific_thing
import module_name as alias
Example
python 
import math
from random import randint

print(math.sqrt(16))
print(randint(1, 6))
Expected output
output 
4.0
(a random number 1-6)
Common mistake — Using from module import * in real projects — it pollutes the namespace and makes it unclear where a name came from. Import explicitly instead.
Practical use — Splitting a project into modules (e.g. engine.py, cli.py) is exactly the modular-architecture pattern used in real tool design — engine separated from interface.

Packages

core · modules

A package is a directory of modules containing an __init__.py file (Python 3 also supports namespace packages without it). Packages let you organize related modules under one importable namespace.

Example
python 
# project structure:
# mytool/
#   __init__.py
#   scanner.py
#   report.py

from mytool import scanner
Practical use — Any devforge-style tool with multiple internal modules (engine, GUI, CLI) is structured as a package once it outgrows a single file.

Virtual environments and pip

core · environment

A virtual environment is an isolated Python install with its own installed packages, separate from your system Python. pip is Python's package installer, used to install third-party libraries.

Syntax
python 
python3 -m venv .venv
source .venv/bin/activate   # macOS/Linux
.venv\Scripts\activate      # Windows
pip install requests
Expected output
output 
(after activation, your prompt shows (.venv) prefix)
Common mistake — Installing packages globally instead of inside a venv. This causes version conflicts between unrelated projects and eventually a broken system Python. Always create a venv per project.
Practical use — Every serious Python project — including every tool in a personal toolkit — should have its own isolated venv with a requirements.txt pinning exact dependency versions.

try, except, else, finally

intermediate · errors

Exception handling lets your program respond to runtime errors instead of crashing. Code that might fail goes in try; the response goes in except; else runs only if no exception occurred; finally always runs, used for cleanup.

Syntax
python 
try:
    risky_code()
except SpecificError as e:
    handle(e)
else:
    only_if_no_error()
finally:
    always_runs()
Example
python

    age = int(input("Age: "))
except ValueError:
    print("That is not a valid number")
else:
    print(f"Age accepted: {age}")
Expected output
output 
Age: abc
That is not a valid number
Common mistake — Using a bare except: that catches everything, including KeyboardInterrupt and genuine bugs you'd want to see. Always catch the specific exception type you expect.
Practical use — Robust CLI tools and network scripts wrap risky operations (parsing, network calls, file I/O) in targeted exception handling so one bad input doesn't crash the whole tool.

advanced · OOP

A class is a blueprint defining attributes (data) and methods (behavior). An object is a specific instance created from that blueprint. Object-oriented programming models a problem as interacting objects rather than a sequence of standalone functions.

Mental model — A class is like a cookie cutter; each object it produces is a cookie — same shape (structure), but each can have different toppings (state).

Constructors: __init__

Encapsulation

advanced · OOP

Encapsulation bundles data and the methods that operate on it, restricting direct external access where appropriate. Python uses a naming convention rather than strict enforcement: a single leading underscore (_name) signals "internal use," double underscore (__name) triggers name mangling.

Example
python 
class Vault:

v = Vault()

print(v._locked)
Expected output
output 
False
Common mistake — Assuming _name or __name actually blocks access from outside the class — Python has no true "private" — it's a convention other developers are expected to respect, not a hard technical barrier.
Practical use — Encapsulation keeps internal implementation details separate from the public interface, so internals can change without breaking code that uses the class.

Descriptors

Threads and the threading module

advanced · concurrency

Threading runs multiple functions concurrently within one process, sharing memory. Due to Python's Global Interpreter Lock (GIL), threads don't give true CPU parallelism for pure-Python code, but they excel at I/O-bound work (waiting on network/disk).

Example
python 
import threading

def worker(n):
    print(f"worker {n} done")

threads = [threading.Thread(target=worker, args=(i,)) for i in range(3)]
for t in threads: t.start()
for t in threads: t.join()
Common mistake — Using threading for CPU-bound work expecting a speedup — the GIL prevents true parallel execution of Python bytecode across threads. Use multiprocessing instead for CPU-bound tasks.
Practical use — Threading is ideal for concurrent network requests — e.g. scanning many hosts at once without waiting for each one sequentially.

Multiprocessing

advanced · concurrency

multiprocessing runs code in separate processes, each with its own Python interpreter and memory space — this bypasses the GIL entirely and gives true parallelism for CPU-bound work.

Example
python 
from multiprocessing import Pool

def square(n):
    return n * n

with Pool(4) as p:
    print(p.map(square, [1, 2, 3, 4]))
Expected output
output 
[1, 4, 9, 16]
Common mistake — Using multiprocessing for I/O-bound work — the overhead of spawning separate processes outweighs the benefit compared to threading or asyncio for tasks that mostly wait on network/disk.
Practical use — Multiprocessing is the right tool for genuinely CPU-heavy work — hashing large files, brute-force computations, image/data processing.

asyncio: async and await

advanced · concurrency

asyncio provides single-threaded concurrency through cooperative multitasking — functions declared async def can pause at await points, letting other async code run while waiting on I/O.

Syntax
python 
async def function():
    result = await other_async_function()
Example
python 
import asyncio

async def fetch(n):
    await asyncio.sleep(1)
    return f"result {n}"

async def main():
    results = await asyncio.gather(fetch(1), fetch(2), fetch(3))
    print(results)

asyncio.run(main())
Expected output
output 
['result 1', 'result 2', 'result 3']  # after ~1s total, not 3s
Common mistake — Calling an async def function without awaiting it — this returns a coroutine object instead of actually running it, a very common and confusing beginner mistake.
Practical use — Asyncio is the standard approach for high-concurrency network clients — e.g. querying hundreds of API endpoints or hosts concurrently with minimal overhead.

Concurrency vs parallelism

advanced · concurrency

Concurrency means dealing with multiple tasks by interleaving progress (not necessarily simultaneous). Parallelism means literally executing multiple tasks at the same instant on multiple CPU cores.

Mental model — One chef switching rapidly between five pots is concurrency. Five chefs each tending one pot simultaneously is parallelism.
Practical use — Choose threading/asyncio for I/O-bound concurrency (waiting on network/disk); choose multiprocessing for CPU-bound parallelism (heavy computation).

Big-O basics

advanced · performance

Big-O notation describes how an algorithm's runtime or memory grows as input size grows. Common classes, from best to worst: O(1), O(log n), O(n), O(n log n), O(n²).

Example
python 
# O(n) - single pass
for item in items:
    process(item)

# O(n^2) - nested loop over same data
for a in items:
    for b in items:
        compare(a, b)
Common mistake — Ignoring Big-O until performance becomes a visible problem — a nested loop that's fine for 100 items can be unusable at 100,000. Consider complexity from the start for anything that processes real-world data volumes.
Practical use — Understanding Big-O tells you why a dict lookup (O(1)) beats scanning a list (O(n)) for repeated membership checks — a very common real-world optimization.

Profiling, caching, and efficient data structures

advanced · performance

Profile before optimizing — use cProfile or timeit to measure where time is actually spent, rather than guessing. functools.lru_cache caches expensive function results automatically.

Example
python 
from functools import lru_cache

@lru_cache(maxsize=None)
def expensive(n):
    return sum(range(n))

print(expensive(1000000))  # slow first call
print(expensive(1000000))  # instant, cached
Common mistake — Optimizing code that isn't actually the bottleneck ("premature optimization"). Always profile first — the slow part is often not where intuition suggests.
Practical use — Caching is a near-free performance win for pure functions called repeatedly with the same arguments — common in recursive algorithms and repeated lookups.

Authentication concepts

real world · backend

Authentication verifies identity. Common approaches: API keys (simple, static secret), JWT tokens (signed, stateless, carry claims), and OAuth (delegated third-party auth). Never store passwords in plaintext — always hash them with a strong algorithm like bcrypt or Argon2.

Example

Practical use — Understanding these patterns is essential before building any API that needs to distinguish and protect per-user data.

Log analysis and file analysis

real world · cybersecurity

Security-relevant log analysis combines regex, string processing, and data structures (like Counter) to detect patterns — repeated failed logins, unusual request rates, known malicious signatures.

Example
python 
from collections import Counter
import re

failed_ips = []
with open("auth.log") as f:
    for line in f:
        if "Failed password" in line:
            m = re.search(r"from (\d+\.\d+\.\d+\.\d+)", line)
            if m:
                failed_ips.append(m.group(1))

print(Counter(failed_ips).most_common(3))
Common mistake — Loading an entire multi-gigabyte log file into memory with .readlines() instead of iterating line-by-line. Iterating a file object directly (as above) streams it lazily instead.
Practical use — This is precisely the kind of parsing engine behind defensive tools that flag brute-force attempts or anomalous access patterns from raw log data.

Step-by-step implementation

1. Data model — define the result shape first:

python 
from dataclasses import dataclass, field
from datetime import datetime

@dataclass
class HostResult:
    host: str
    reachable: bool
    open_ports: list[int] = field(default_factory=list)
    checked_at: datetime = field(default_factory=datetime.now)

2. Async scanning engine — concurrent, non-blocking checks:

python 
import asyncio
import socket

async def check_port(host: str, port: int, timeout: float = 1.0) -> bool:
    try:
        conn = asyncio.open_connection(host, port)
        reader, writer = await asyncio.wait_for(conn, timeout=timeout)
        writer.close()
        await writer.wait_closed()
        return True
    except (asyncio.TimeoutError, OSError):
        return False

async def scan_host(host: str, ports: list[int]) -> HostResult:
    results = await asyncio.gather(*(check_port(host, p) for p in ports))
    open_ports = [p for p, ok in zip(ports, results) if ok]
    return HostResult(host=host, reachable=bool(open_ports), open_ports=open_ports)

3. Storage layer — persist results with parameterized queries:

python 
import sqlite3
from contextlib import contextmanager

@contextmanager
def get_db(path: str = "recon.db"):
    conn = sqlite3.connect(path)
    conn.execute("""CREATE TABLE IF NOT EXISTS results (
        host TEXT, reachable INTEGER, open_ports TEXT, checked_at TEXT
    )""")
    try:
        yield conn
        conn.commit()
    finally:
        conn.close()

def save_result(result: HostResult) -> None:
    with get_db() as conn:
        conn.execute(
            "INSERT INTO results VALUES (?, ?, ?, ?)",
            (result.host, int(result.reachable), str(result.open_ports), result.checked_at.isoformat())
        )

4. CLI entrypoint — tie it together:

python 
import argparse
import asyncio
import logging

logging.basicConfig(level=logging.INFO)

def main():
    parser = argparse.ArgumentParser(description="Authorized recon toolkit")
    parser.add_argument("hosts", nargs="+", help="hosts to check (lab-authorized only)")
    parser.add_argument("--ports", type=int, nargs="+", default=[22, 80, 443])
    args = parser.parse_args()

    async def run():
        for host in args.hosts:
            result = await scan_host(host, args.ports)
            save_result(result)
            logging.info(f"{result.host}: reachable={result.reachable} ports={result.open_ports}")

    asyncio.run(run())

if __name__ == "__main__":
    main()

Build a retry decorator Hard

Write a decorator @retry(times=3) that retries a function up to N times if it raises an exception, then re-raises the last exception if all attempts fail.

python 
import functools
import time

def retry(times=3, delay=0.5):
    def decorator(func):
        @functools.wraps(func)
        def wrapper(*args, **kwargs):
            last_exc = None
            for attempt in range(1, times + 1):
                try:
                    return func(*args, **kwargs)
                except Exception as e:
                    last_exc = e
                    print(f"Attempt {attempt} failed: {e}")
                    time.sleep(delay)
            raise last_exc
        return wrapper
    return decorator

@retry(times=3)
def flaky():
    import random
    if random.random() < 0.7:
        raise ConnectionError("simulated failure")
    return "success"

print(flaky())
Implement a thread-safe counter Hard

Multiple threads incrementing a shared counter can produce a wrong final count due to race conditions. Implement a counter class that is safe under concurrent access using a lock.

Without the lock, concurrent read-modify-write on _value can lose increments.

python 
import threading

class SafeCounter:
    def __init__(self):
        self._value = 0
        self._lock = threading.Lock()

    def increment(self):
        with self._lock:
            self._value += 1

    @property
    def value(self):
        return self._value

counter = SafeCounter()
threads = [threading.Thread(target=lambda: [counter.increment() for _ in range(1000)]) for _ in range(10)]
for t in threads: t.start()
for t in threads: t.join()
print(counter.value)  # always 10000, not a race-corrupted lower number
Design a plugin-style architecture Expert

Build a small framework where "checks" (e.g. port-open, DNS-resolves, ping) are registered as plugins and run against a target, without the core engine needing to know about each check type in advance.

New checks are added by writing a new Check subclass and registering it — the engine never changes.

python 
from abc import ABC, abstractmethod

class Check(ABC):
    name: str
    @abstractmethod
    def run(self, target: str) -> bool: ...

class DNSCheck(Check):
    name = "dns_resolves"
    def run(self, target: str) -> bool:
        import socket
        try:
            socket.gethostbyname(target)
            return True
        except socket.gaierror:
            return False

class CheckEngine:
    def __init__(self):
        self._checks: list[Check] = []

    def register(self, check: Check):
        self._checks.append(check)

    def run_all(self, target: str) -> dict[str, bool]:
        return {c.name: c.run(target) for c in self._checks}

engine = CheckEngine()
engine.register(DNSCheck())
print(engine.run_all("example.com"))
