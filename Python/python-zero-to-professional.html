What is it?

Python is an interpreted language: a program called the interpreter reads your code and executes it directly, line by line, instead of compiling it to a standalone binary first. You can run Python two main ways: the REPL (Read-Eval-Print Loop, started by typing python or python3 in a terminal) for quick one-off experiments, or a script — a .py file — for anything you want to save and re-run.

Why it matters

Every exercise in this course assumes you can get code running. Understanding the difference between "typing directly into the REPL" and "writing a file and running it" avoids a huge amount of early confusion, especially when copying multi-line examples.

Mental model

Think of the REPL as a scratchpad — it evaluates one statement at a time and immediately shows results, but nothing is saved. A script is a recipe written down in a file that the interpreter reads from top to bottom, in one pass, when you run it.

Syntax & example
terminal
$ python3 --version
Python 3.12.4
$ python3
>>> 2 + 2
4
>>> exit()
$ python3 hello.py
Expected output (REPL)4
Step-by-step
  • python3 --version confirms Python is installed and which version you have.
  • Running python3 with no filename drops you into the interactive REPL.
  • Typing 2 + 2 and pressing Enter evaluates it immediately and prints 4.
  • exit() (or Ctrl-D) leaves the REPL.
  • python3 hello.py runs every line inside hello.py from top to bottom.
Common mistake

Typing python on a system where that command points to Python 2 (or doesn't exist at all), then being confused when syntax from this course fails. On many systems the modern interpreter is explicitly named python3.

Correct approach

Run python3 --version first. If it reports 3.9 or newer, you're set for this entire course. Use python3 consistently in your terminal unless you've confirmed python already points to Python 3.

Practical use & edge cases

Use the REPL to test a single expression or check how a function behaves. Use scripts for anything longer than a few lines, anything you want to keep, or anything a teammate needs to run later.

What is it?

A comment starts with # and is ignored entirely by the interpreter. It exists purely for humans reading the code.

Why it matters

Code explains what happens; comments explain why. Professional Python leans on comments sparingly but precisely — for non-obvious decisions, not for narrating obvious lines.

Mental model

The interpreter deletes everything from # to the end of the line before it even looks at the syntax. Comments have zero runtime effect.

Syntax & example
python
# convert Celsius to Fahrenheit
celsius = 22
fahrenheit = celsius * 9 / 5 + 32  # standard conversion formula
print(fahrenheit)
Output71.6
Common mistake

Writing comments that just restate the code, like # set x to 5 above x = 5. This adds noise without adding information.

Correct version

Reserve comments for intent: # retry limit chosen to match the API's rate-limit window tells the reader something the code alone cannot.

Practical use & edge cases

Docstrings (triple-quoted strings right under a function/class definition) are a related but distinct tool for documenting what something does — you'll meet those in Level 03.

Micro-challenge

# using 9/5 instead of 1.8 to keep the formula recognizable to readers
fahrenheit = celsius * 9 / 5 + 32
What is it?

A variable is a name bound to a value using =. Once assigned, you use the name in place of the value.

Why it matters

Nearly every line of Python you write will create, read, or update a variable. Getting the mental model right here prevents confusion later with mutability and shared references.

Mental model

In Python, a variable is not a box that holds a value — it's a label attached to an object living in memory. x = 5 creates the integer object 5 and attaches the label x to it. y = x attaches a second label to the same object; it does not copy it.

Syntax & example
python
age = 28
city = "Baku"
age = age + 1
print(age, city)
Output29 Baku
How Python evaluates this

The right-hand side of = is always evaluated completely first (producing an object), and only then is the name on the left attached to that resulting object. So age = age + 1 reads the current object bound to age, computes a new integer, and re-binds age to that new object — the old 28 object is untouched (integers are immutable).

Common mistake

NameError: name 'x' is not defined — using a variable before it has ever been assigned, often from a typo in the name.

Correct version

Assign before use, and double-check spelling/case — Python names are case-sensitive, so Age and age are different variables.

Practical use & edge cases

Multiple assignment is common: x, y = 1, 2 or a = b = 0 (both names point at the same initial object).

Predict the output

a = 10
b = a
a = 20
print(b)

Output10

Why: b = a copied the reference to the integer 10, not a link to the name a. Re-assigning a to a new object 20 doesn't move b.

What is it?

Identifiers (names for variables, functions, etc.) must start with a letter or underscore, contain only letters/digits/underscores, and cannot be one of Python's ~35 reserved keywords (if, for, class, ...).

Why it matters

Consistent naming (PEP 8's snake_case for variables and functions) is one of the cheapest ways to make Python code readable to any other Python developer, including future you.

Syntax & example
python
total_price = 42.50      # good: snake_case
user_count = 3           # good: descriptive
x1 = "temp"              # legal, but not descriptive
Common mistake

SyntaxError from naming a variable class, for, or starting a name with a digit like 1st_place.

Correct version

Use first_place, and avoid shadowing keywords or built-in names like list, str, or type — Python allows it, but it silently hides the built-in for the rest of that scope.

Practical use & edge cases

Conventions you'll see throughout this course: snake_case for variables/functions, PascalCase for classes (Level 04), UPPER_CASE for constants.

Fix the code

Which of these are invalid Python identifiers: 2fast, _secret, my-var, class, total_1?

Invalid: 2fast (starts with a digit), my-var (hyphens aren't allowed — Python would read it as subtraction), class (reserved keyword). Valid: _secret, total_1.

What is it?

A literal is a value written directly in source code. Python's core scalar types are int (whole numbers), float (decimals), str (text, in quotes), bool (True/False), and None (the deliberate absence of a value).

Why it matters

Every piece of data your program manipulates starts as one of these types (or a collection built from them, covered in Level 02).

Syntax & example
python
count = 7            # int
price = 19.99        # float
name = "Ada"         # str
is_active = True     # bool
result = None        # None: "nothing here yet"
Why this behavior exists

None is not the same as 0, an empty string, or False — it specifically means "no value has been set." Functions that don't explicitly return anything return None automatically, which you'll rely on later to detect "did this actually produce a result?"

Common mistake

Writing "7" when you mean the number 7. "7" + "3" gives the string "73", not 10, because both are strings and + concatenates text.

Correct version

7 + 3 gives 10. Convert strings from user input with int() or float() before doing arithmetic on them (covered in 1.6).

Predict the output

print(type(True))
print(True + 1)

Output<class 'bool'>
2

Why: bool is technically a subtype of int in Python — True behaves as 1 and False as 0 in arithmetic.

What is it?

type(value) tells you a value's type. int(x), float(x), str(x), bool(x) convert (or "cast") a value into another type where a sensible conversion exists.

Why it matters

Input from users, files, and APIs almost always arrives as text (str). You must explicitly convert it before doing math on it.

Syntax & example
python
raw = "21"
age = int(raw)
print(type(raw), type(age))
print(age + 1)
Output<class 'str'> <class 'int'>
22
Common mistake

int("21.5") raises ValueError: invalid literal for int() with base 10: '21.5' — int() cannot parse a decimal point directly.

Correct version

Convert through float() first if decimals are possible: int(float("21.5")), or use float("21.5") if you actually want to keep the decimal.

Practical use & edge cases

bool(x) follows Python's "truthiness" rules: 0, 0.0, "", None, and empty collections convert to False; almost everything else converts to True. This matters heavily once you reach if statements in Level 02.

What is it?

Arithmetic: + - * / // % **. Comparison: == != < > <= >= (always produce a bool). Boolean logic: and, or, not.

Syntax & example
python
print(17 / 5)    # true division
print(17 // 5)   # floor division
print(17 % 5)    # remainder (modulo)
print(2 ** 5)    # exponent
print(3 > 2 and 1 < 5)
Output3.4

True
Why this behavior exists

Python separates / (always returns a float) from // (floor division, rounds toward negative infinity) so you never accidentally lose precision silently — if you want an integer result you must ask for it explicitly.

Common mistake

Confusing = (assignment) with == (comparison): if x = 5: is actually a SyntaxError in Python (unlike some other languages), which at least catches the mistake early.

Correct version

if x == 5: compares; x = 5 assigns. Python's syntax rule that assignment can't appear inside an if condition prevents the classic "accidental assignment" bug entirely.

Practical use & edge cases

-7 // 2 is -4, not -3 — floor division always rounds down (toward negative infinity), which surprises people coming from languages that truncate toward zero.

print(-7 % 2)

What is it?

print() writes text to the terminal. An f-string (f"...") lets you embed expressions directly inside a string using { }.

Syntax & example
python
name = "Ada"
score = 93.456
print(f"{name} scored {score:.1f}%")
print("a", "b", "c", sep="-")
OutputAda scored 93.5%
a-b-c
Step-by-step
  • f"..." tells Python this string contains embedded expressions.
  • {score:.1f} formats the float to one decimal place.
  • print()'s sep keyword argument changes the default single-space separator between multiple arguments.
Common mistake

Forgetting the f prefix: print("{name}") prints the literal text {name} instead of substituting the variable.

Correct version

print(f"{name}"). The f must come immediately before the opening quote.

Practical use & edge cases

Older code you'll encounter may use .format() or %-formatting — f-strings (Python 3.6+) are the modern, preferred style for new code.

Write code

Given items = 3 and price = 4.5, print: 3 items cost $13.50 using one f-string.

items = 3
price = 4.5
print(f"{items} items cost ${items * price:.2f}")
What is it?

input(prompt) pauses the program, shows the prompt, and returns whatever the user types — always as a str, even if they type digits.

Syntax & example
python
name = input("What's your name? ")
print(f"Hello, {name}!")
Expected output (varies by input)What's your name? Leyla
Hello, Leyla!
Common mistake

Treating input() results as numbers directly: age = input("Age: ") then age + 1 raises TypeError: can only concatenate str (not "int") to str.

Correct version

age = int(input("Age: ")) converts immediately, at the point of input, so the rest of the program can treat age as a real number.

Practical use & edge cases

Real programs validate input rather than trusting it blindly — a user typing letters where a number is expected will crash int() with a ValueError unless you handle it (Level 05 covers try/except for this).

What is it?

Python uses indentation (whitespace at the start of a line) to mark which lines belong to a block — instead of curly braces { } like many other languages.

Why does Python work this way?

The language's designers made indentation mandatory rather than cosmetic, on the reasoning that since almost every programmer indents code for readability anyway, making that indentation the actual syntax removes the possibility of code that "looks" one way but behaves another (a real source of bugs in brace-based languages when formatting and logic disagree).

Syntax & example
python
if 5 > 3:
    print("five is bigger")
    print("this line is also inside the if")
print("this line always runs")
Outputfive is bigger
this line is also inside the if
this line always runs
Common mistake

IndentationError: unexpected indent or IndentationError: expected an indented block — mixing tabs and spaces, or forgetting to indent the line(s) after a colon :.

Correct version

Pick one convention (4 spaces is the PEP 8 standard) and let your editor enforce it consistently. Never mix tabs and spaces in the same file.

Practical use & edge cases

Every block-introducing statement ends in a colon: if, for, while, def, class, try. The next line must be indented one level deeper than the statement that opened the block.

Debug code

This code raises IndentationError. Why?

if 10 > 5:
print("yes")

The line after if 10 > 5: must be indented — Python expects a block and finds none. Fix: indent print("yes") by 4 spaces.

What is it?

Conditional statements run a block only when a condition evaluates to True. elif checks additional conditions in order; else catches everything else.

Mental model

Python evaluates conditions top to bottom and runs the first block whose condition is true, then skips the rest of the chain entirely — even if a later condition would also be true.

Syntax & example
python
score = 82
if score >= 90:
    grade = "A"
elif score >= 80:
    grade = "B"
else:
    grade = "C"
print(grade)
OutputB
Common mistake

Writing separate if statements instead of elif when the branches are mutually exclusive — this wastes evaluation and can cause multiple blocks to fire.

Correct version

Use elif when only one branch should ever run for a given input; use separate if statements only when the checks are genuinely independent.

Practical use & edge cases

Nested conditions are valid but readability suffers fast — prefer combining conditions with and/or or restructuring with early returns (Level 03) over deep nesting.

Predict the output

x = 5
if x > 0:
  print("positive")
if x > 3:
  print("big")

Outputpositive
big

Both print because these are two separate if statements, not an if/elif chain — both conditions are independently checked.

What is it?

A for loop runs its block once for each item in an iterable (a list, string, range, etc.), binding the loop variable to the current item each time.

Mental model

Unlike C-style for(i=0;...) loops, Python's for is fundamentally "for each item in this collection," not "count from A to B" — counting is done by looping over range(), a separate tool (2.4).

Syntax & example
python
fruits = ["apple", "banana", "cherry"]
for fruit in fruits:
    print(fruit.upper())
OutputAPPLE
BANANA
CHERRY
Practical use & edge cases

enumerate(fruits) gives you both index and value; zip(a, b) lets you loop over two sequences in lockstep. Both are covered fully in Level 03's functional-tools lessons.

Common mistake

Modifying a list while iterating over it directly (e.g. removing items inside the loop) — this silently skips elements because the list shifts under the iterator.

Correct version

Iterate over a copy — for item in list(original): — or build a new list with a comprehension instead of mutating during iteration.

Write code

Given nums = [4, 9, 15, 2], print each number and whether it's even or odd.

nums = [4, 9, 15, 2]
for n in nums:
    kind = "even" if n % 2 == 0 else "odd"
    print(f"{n} is {kind}")
What is it?

while condition: repeats a block as long as the condition stays true. break exits a loop immediately; continue skips to the next iteration; pass is a no-op placeholder where syntax requires a statement.

Syntax & example
python
attempts = 0
while attempts < 3:
    guess = input("Guess the number: ")
    if guess == "7":
        print("Correct!")
        break
    attempts += 1
else:
    print("Out of attempts")
Expected output (varies)Correct! (if guessed) or Out of attempts
Why this behavior exists

A while loop's else clause (uncommon but real) runs only if the loop finished without hitting break — useful for "search and report if not found" patterns.

Common mistake

Forgetting to update the loop's condition variable, creating an infinite loop — e.g. forgetting attempts += 1 above.

Correct version

Always verify there's a path to the loop condition becoming false, or an explicit break that will definitely be reached.

Practical use & edge cases

Prefer for when you know the number of iterations in advance (or are iterating a collection); reach for while when the stopping condition depends on something computed during the loop.

Debug code

What is it?

range(stop), range(start, stop), and range(start, stop, step) generate a sequence of numbers lazily — used almost exclusively for counting loops.

Syntax & example
python
for i in range(1, 6):
    print(i, end=" ")
print()
for i in range(10, 0, -2):
    print(i, end=" ")
Output1 2 3 4 5
10 8 6 4 2
Common mistake

Assuming range(1, 5) includes 5 — stop is always exclusive, so this gives 1, 2, 3, 4.

Correct version

Use range(1, 6) to include 5, or think of it as "count from start up to but not including stop."

Practical use & edge cases

range doesn't build a full list in memory — it produces numbers on demand, which matters once you loop over very large ranges.

What is it?

A string is an ordered, immutable sequence of characters. You can index (s[0]), slice (s[1:4]), and call methods like .upper(), .strip(), .split(), .replace(), .join().

Why are strings immutable?

Immutability lets Python safely share the same string object across many variables without risk that one part of a program silently mutates text another part depends on. Every string "modification" method actually returns a brand-new string.

Syntax & example
python
s = "  Hello, Python!  "
print(s.strip())
print(s.strip().lower())
print(s[2:7])
words = "a,b,c".split(",")
print(words)
print("-".join(words))
OutputHello, Python!
hello, python!
Hello
['a', 'b', 'c']
a-b-c
Common mistake

TypeError: 'str' object does not support item assignment from trying s[0] = "H".

Correct version

Build a new string instead: s = "H" + s[1:], or use a method that returns a modified copy.

Edge cases

Negative indices count from the end (s[-1] is the last character). Slicing never raises an error for out-of-range bounds — s[2:1000] just returns up to the end of the string.

A step of -1 in a slice walks the string backward from end to start — a common idiom for reversing a sequence.

What is it?

A list ([ ]) is an ordered, mutable collection that can hold any mix of types. Core operations: .append(), .insert(), .remove(), .pop(), .sort(), indexing, slicing.

Why are lists mutable?

Lists model collections that genuinely grow and change over a program's life — a shopping cart, a queue of tasks. Making them mutable avoids the cost of rebuilding an entire new collection for every small change. The tradeoff is that two variables can point to the same list, so mutating through one name affects the other.

Syntax & example
python
nums = [3, 1, 4, 1, 5]
nums.append(9)
nums.sort()
print(nums)
print(nums[1:4])
Output[1, 1, 3, 4, 5, 9]
[1, 3, 4]
What is happening in memory

a = [1, 2]; b = a makes b reference the exact same list object as a. b.append(3) changes the one underlying list, so a shows the change too. To get an independent copy, use b = a.copy() or b = list(a) — and note that's still only a shallow copy (Level 04 covers deep copies for nested structures).

Common mistake

Expecting b = a to create an independent list, then being confused when changes to b show up in a.

Correct version

b = a.copy() creates a new list with the same elements; mutating b no longer affects a (for simple, non-nested elements).

Predict the output

x = [1, 2, 3]
y = x
y.append(4)
print(x)

Output[1, 2, 3, 4]

Why: y = x didn't copy the list — it made y a second name for the same object. Appending through y mutates the one list both names refer to.

What is it?

A tuple (( )) is an ordered, immutable collection — once created, its contents (and their positions) can't change.

Why does this matter?

Immutability signals intent: a tuple says "this is a fixed record," like coordinates (x, y) or an RGB color (255, 0, 0). It's also the type Python uses internally for multiple return values and can safely be used as a dictionary key (lists cannot).

Syntax & example
python
point = (3, 4)
x, y = point           # unpacking
print(x, y)
coords = {(0, 0): "origin", (1, 1): "diagonal"}
print(coords[(0, 0)])
Output3 4
origin
Common mistake

Writing (4) expecting a one-element tuple — it's just the integer 4 in parentheses. A single-element tuple needs a trailing comma: (4,).

Correct version

single = (4,). The comma, not the parentheses, is what actually makes it a tuple.

Write code

name, age, role = ("Ada", 36, "Engineer")
print(f"{name} is a {age}-year-old {role}.")
What is it?

A set ({ } or set()) is an unordered collection of unique, hashable items. Duplicates are automatically discarded.

Why it matters

Checking item in a_set is much faster than item in a_list for large collections, and de-duplication is a one-line operation: set(my_list).

Syntax & example
python
tags = {"python", "web", "python", "cli"}
print(tags)
print("web" in tags)
a = {1, 2, 3}
b = {2, 3, 4}
print(a & b)   # intersection
print(a | b)   # union
Expected output (order may vary){'python', 'web', 'cli'}
True
{2, 3}
{1, 2, 3, 4}
Common mistake

Writing empty = {} expecting an empty set — that syntax actually creates an empty dictionary.

Correct version

Use empty = set() for an empty set.

Edge cases

Sets can only contain hashable (effectively immutable) items — you can put tuples in a set, but not lists or other sets.

What is it?

A dictionary ({key: value}) maps unique keys to values, with fast lookup by key. Since Python 3.7, dictionaries preserve insertion order.

Why it matters

Dictionaries are how you model almost any real-world "record" — a user profile, a config file, an API response — before you learn classes in Level 04.

Syntax & example
python
user = {"name": "Ada", "age": 36}
user["role"] = "Engineer"     # add a new key
print(user.get("email", "not set"))
for key, value in user.items():
    print(key, "-", value)
Outputnot set
name - Ada
age - 36
role - Engineer
Common mistake

KeyError: 'email' from user["email"] when the key doesn't exist.

Correct version

Use user.get("email", default_value) when a key might be missing, or check with "email" in user first.

Practical use & edge cases

What is it?

A recursive function calls itself to solve a smaller version of the same problem, until it reaches a base case simple enough to answer directly.

Mental model

Each call waits on a call stack for the call(s) it made to finish. Without a base case that stops the recursion, calls pile up until Python raises RecursionError: maximum recursion depth exceeded.

Syntax & example
python
def factorial(n):
    if n <= 1:              # base case
        return 1
    return n * factorial(n - 1)   # recursive case

print(factorial(5))
Output120
How Python evaluates this

factorial(5) calls factorial(4), which calls factorial(3), and so on down to factorial(1), which returns 1 directly. Each waiting call then multiplies as the stack unwinds: 1 → 2 → 6 → 24 → 120.

Common mistake

Forgetting the base case, or writing it so it's never actually reached (e.g. calling factorial(n) instead of factorial(n - 1)), causing infinite recursion.

Correct version

Always ensure the recursive call moves strictly toward the base case, and test the base case manually first.

When this behavior matters

Recursion shines for naturally nested/tree-shaped problems (parsing, file-system traversal). For simple counting or accumulation, an equivalent loop is usually clearer and avoids Python's relatively low default recursion limit (~1000).

A decorator is a function that takes another function, wraps it with extra behavior, and returns the wrapped version. The @decorator_name syntax right above a def is shorthand for func = decorator_name(func).

    @wraps(func)

Build a @retry(times=3) decorator (a decorator that itself takes an argument — a "decorator factory") that re-attempts a failing function up to times times before letting the last exception propagate, printing a message on each retry.

retry.py
from functools import wraps

def retry(times=3):
    def decorator(func):
        @wraps(func)
        def wrapper(*args, **kwargs):
            last_error = None
            for attempt in range(1, times + 1):
                try:
                    return func(*args, **kwargs)
                except Exception as e:
                    last_error = e
                    print(f"Attempt {attempt} failed: {e}")
            raise last_error
        return wrapper
    return decorator

@retry(times=3)
def flaky():
    raise ValueError("simulated failure")

Syntax & example
python
import os
import requests
import time

def get_with_retries(url, headers, max_attempts=3):
    for attempt in range(1, max_attempts + 1):
        try:
            response = requests.get(url, headers=headers, timeout=5)
            if response.status_code == 200:
                return response.json()
            if response.status_code == 429:      # rate limited
                time.sleep(2 ** attempt)
                continue
            response.raise_for_status()
        except requests.exceptions.RequestException as e:
            print(f"Attempt {attempt} failed: {e}")
    return None

What is it?

A traceback shows the exact chain of calls that led to an error, read from top (where the call started) to bottom (the actual line and exception type that failed). pdb (Python's built-in debugger) lets you pause execution and inspect live variables instead of guessing from print statements alone.

Systematic debugging workflow
  • Reproduce the bug reliably — a bug you can't trigger on demand is very hard to fix confidently.
  • Read the traceback bottom-up: the last line names the exception type and message; the line above it shows exactly where it happened.
  • Isolate — narrow down which variable or input actually triggers the failure, ideally with a minimal reproducing example.
  • Form a hypothesis about the cause, then test it directly (print, breakpoint, or a small script) rather than guessing at a fix blind.
  • Fix, then verify — confirm the original reproduction case now passes, and add a regression test (8.4).

What is it?

Security-aware Python isn't a separate skill bolted on at the end — it's a set of habits applied throughout everything you've already learned. This lesson consolidates them into one reference.

The checklist
  • Input validation: never trust external input (user, file, API, environment) — validate type, range, and format at the boundary (Level 05).
  • SQL: always use parameterized queries, never string concatenation (Level 07).
  • Subprocess: pass argument lists, avoid shell=True with any input you don't fully control (Level 07).
  • Path traversal: if a user supplies a filename, don't trust it directly — a value like "../../etc/passwd" could escape an intended directory. Resolve and verify the final path stays within an allowed base directory before using it.
  • Secrets: read API keys, passwords, and tokens from environment variables or a secrets manager — never hard-code them in source, never commit them to version control.
  • Deserialization: never use pickle.load() on data from an untrusted source — unlike json, unpickling can execute arbitrary code embedded in the data.
  • Dependencies: third-party packages can have vulnerabilities or be malicious — pin versions in requirements.txt, and update deliberately rather than blindly.
  • Logging: never log secrets, passwords, or full sensitive personal data in plaintext (Level 08).
  • Least privilege: a script or service should have only the permissions and access it actually needs — a report-generation script has no legitimate need for database write access, for example.
Syntax & example: safe path handling
python
from pathlib import Path

def safe_open(base_dir, user_filename):
    base = Path(base_dir).resolve()
    target = (base / user_filename).resolve()
    if not target.is_relative_to(base):
        raise ValueError("Invalid path: outside the allowed directory")
    return open(target)

Correct version

What is it?

Concurrency means structuring a program to make progress on more than one task without waiting for each to fully finish before starting the next. Python offers three main tools: threading (multiple threads in one process), multiprocessing (multiple separate processes), and asyncio (a single thread cooperatively switching between tasks).

Why does Python offer three different tools?

They solve genuinely different problems. Python's Global Interpreter Lock (GIL) means only one thread executes Python bytecode at a time even with multiple threads — so threading doesn't speed up CPU-heavy work, but it's fine for I/O-bound work (waiting on network/disk), because a waiting thread releases the GIL. Multiprocessing uses separate processes (each with its own interpreter and memory), genuinely running in parallel on multiple CPU cores — the right tool for CPU-heavy work. asyncio uses a single thread and an event loop to juggle many I/O-bound tasks efficiently without the overhead of threads or processes at all.

Mental model

Think of a chef (single thread) cooking several dishes: while water boils for pasta (I/O wait), the chef chops vegetables for another dish instead of standing idle — that's the idea behind both threading-for-I/O and asyncio. Multiprocessing is instead hiring several chefs, each with their own kitchen, genuinely cooking in parallel.

Common mistake

Using threading to speed up a CPU-heavy computation (like number crunching) expecting a proportional speedup — the GIL prevents true parallel execution of Python code across threads.

Correct version

Use multiprocessing for CPU-bound work that needs real parallelism; use threading or asyncio for I/O-bound work (network requests, file/database waits) where most time is spent waiting, not computing.

Design a solution

You need to (a) resize 10,000 images on disk and (b) download 10,000 URLs. Which concurrency tool fits each task better?

(a) Image resizing is CPU-bound → multiprocessing to use multiple cores. (b) Downloading URLs is I/O-bound (mostly waiting on the network) → asyncio or threading, either of which can run many downloads concurrently without needing multiple CPU cores.

What is it?

async def defines a coroutine function. await, used only inside a coroutine, pauses that coroutine at an I/O wait and lets the event loop run other coroutines in the meantime, resuming this one once the awaited operation completes.

Syntax & example
python
import asyncio

async def fetch_page(name, delay):
    print(f"Start fetching {name}")
    await asyncio.sleep(delay)     # simulates waiting on network I/O
    print(f"Finished fetching {name}")
    return name

async def main():
    results = await asyncio.gather(
        fetch_page("A", 2),
        fetch_page("B", 1),
    )
    print(results)

asyncio.run(main())
OutputStart fetching A
Start fetching B
Finished fetching B
Finished fetching A
['A', 'B']
Why does async require await?

await marks the exact points where a coroutine is willing to be paused — this is what makes asyncio cooperative rather than automatic: the event loop can only switch to another task at an explicit await, never in the middle of ordinary, non-awaited code. This makes reasoning about shared state far simpler than with threads, where a switch can happen at almost any instruction.

What is happening: why B finishes before A

Both coroutines start immediately via asyncio.gather. fetch_page("B", 1) only needs to wait 1 second, so it resumes and finishes first, even though fetch_page("A", 2) was started first — this interleaving is the entire point of concurrency here.

Common mistake

Blocking inside async code: calling a slow, synchronous, non-async function (like time.sleep() or a blocking network call) inside a coroutine — this blocks the entire event loop, freezing every other concurrent task, defeating the whole purpose.

Correct version

Use the async-aware equivalent (asyncio.sleep() instead of time.sleep(), an async HTTP library instead of requests) for anything that runs inside a coroutine.

Predict the output

If you called fetch_page("A", 2) and fetch_page("B", 1) with regular (non-async, non-gathered) sequential calls plus real time.sleep(), roughly how long would the whole thing take compared to the asyncio.gather version?

Sequentially: about 3 seconds total (2 + 1, one after the other). With asyncio.gather: about 2 seconds total (they overlap; the total time is roughly the longest single wait, not the sum).

What is it?

A task is I/O-bound if most of its time is spent waiting on something external (network, disk, another process) rather than computing. It's CPU-bound if most of its time is spent actually calculating on the CPU. This diagnosis determines which concurrency tool (if any) will actually help.

Why this behavior matters

Adding concurrency to a CPU-bound problem using threads or asyncio does nothing useful — there's no waiting to overlap, and Python's GIL prevents threads from computing in true parallel anyway. Adding multiprocessing to a lightly-loaded I/O-bound problem adds unnecessary complexity and process-startup overhead for no real benefit.

Practical diagnostic
  • Does the task call requests, hit a database, read a large file, or otherwise wait on something outside the CPU? → likely I/O-bound → asyncio or threading.
  • Does the task do heavy math, image/video processing, or large in-memory data transformation with no external waiting? → likely CPU-bound → multiprocessing.
  • Not sure? Profile it first (Level 08's tools apply here too) rather than guessing — premature or wrong-tool concurrency adds real complexity for no benefit.
Common mistake

Reaching for concurrency as a first fix for "my script is slow" without first identifying where the time is actually going.

Correct version

Measure first (even a simple time.time() around suspected slow sections), identify whether the bottleneck is waiting or computing, then apply the matching tool — or sometimes discover the real fix is a better algorithm, not concurrency at all.

Recall

I/O-bound — nearly all the time is spent waiting on the network, not computing. Running the downloads concurrently with asyncio or threads would likely cut the total time dramatically.

What is it?

A repeatable cycle professional developers use, whether working alone or on a team: Problem → Plan → Implement → Run → Debug → Test → Refactor → Document → Ship.

Why this workflow exists

Skipping straight from "problem" to "implement" without planning tends to produce code that solves the wrong problem efficiently. What "code that works" vs. "code that is maintainable" means in practice
  • Works: produces the correct output for the cases you happened to try.
  • Maintainable: also handles bad input predictably, fails with clear errors rather than silent wrong answers, has tests that catch regressions, is organized so a new contributor can find what they need, and is documented well enough to use without reading every line of implementation.

import re
from collections import Counter

LINE_PATTERN = re.compile(r"(GET|POST) (\S+) (\d{3})")

def parse_log(path):
    status_counts = Counter()
    path_counts = Counter()
    with open(path) as f:
        for line in f:
            match = LINE_PATTERN.search(line)
            if not match:
                continue
            _, request_path, status = match.groups()
            status_counts[status] += 1
            path_counts[request_path] += 1
    return status_counts, path_counts

import json
from functools import wraps
from pathlib import Path

NOTES_FILE = Path("notes.json")

def autosave(method):
    @wraps(method)
    def wrapper(self, *args, **kwargs):
        result = method(self, *args, **kwargs)
        self.save()
        return result
    return wrapper

class NotesApp:
    def __init__(self):
        self.notes = json.loads(NOTES_FILE.read_text()) if NOTES_FILE.exists() else []

    @autosave
    def add(self, text):
        self.notes.append(text)

    @autosave
    def delete(self, index):
        del self.notes[index]

    def search(self, keyword):
        return (note for note in self.notes if keyword.lower() in note.lower())

import sqlite3

def get_connection(path="expenses.db"):

Purpose & problem statement

Check the availability of a list of URLs concurrently using asyncio, and measure how much faster this is than a sequential version — making Level 09's concurrency lesson concrete.

async_checker.py
import asyncio
import time
import aiohttp

async def check_url(session, url):
    try:
        async with session.get(url, timeout=5) as response:
            return url, response.status
    except Exception as e:
        return url, f"error: {e}"

async def check_all(urls):
    async with aiohttp.ClientSession() as session:
        tasks = [check_url(session, url) for url in urls]
        return await asyncio.gather(*tasks)

urls = ["https://python.org", "https://pypi.org", "https://docs.python.org"]
start = time.time()
results = asyncio.run(check_all(urls))
for url, status in results:
    print(url, status)
print(f"Total time: {time.time() - start:.2f}s")
Why this works

All URL checks are started together and awaited concurrently via asyncio.gather — total time is roughly the slowest single check, not the sum of all of them, unlike calling requests.get for each URL one after another.

Testing & edge cases

Include a deliberately unreachable URL in the list and confirm one failure doesn't prevent the others from completing (each check_url call catches its own exception independently).

Note on dependencies

aiohttp (an async-native HTTP client, installed via pip) is used here instead of requests, because requests is synchronous/blocking and would freeze the whole event loop if awaited naively — directly illustrating Level 09's "blocking inside async code" mistake.

Extensions

Add a concurrency limit (asyncio.Semaphore) so checking thousands of URLs doesn't open an unbounded number of simultaneous connections.

import os
import logging
import subprocess
from pathlib import Path

logging.basicConfig(level=logging.INFO, format="%(asctime)s %(levelname)s %(message)s")
logger = logging.getLogger(__name__)

ALLOWED_DIR = Path("workspace").resolve()

def resolve_safe_path(user_filename):
    target = (ALLOWED_DIR / user_filename).resolve()
    if not target.is_relative_to(ALLOWED_DIR):
        raise ValueError(f"Path escapes allowed directory: {user_filename}")
    return target

def convert_file(user_filename):
    target = resolve_safe_path(user_filename)
    if not target.exists():
        raise FileNotFoundError(target)
    logger.info(f"Converting file: {target.name}")
    result = subprocess.run(
        ["gzip", "-k", str(target)],
        capture_output=True, text=True, timeout=30,
    )
    if result.returncode != 0:
        logger.error(f"Conversion failed for {target.name}")
    return result.returncode == 0

from datetime import datetime

def add_task(conn, title, priority, due_date):
    with conn:
        conn.execute(
            "INSERT INTO tasks (title, priority, due_date) VALUES (?, ?, ?)",
            (title, priority, due_date),
        )

def complete_task(conn, task_id):
    with conn:
        conn.execute("UPDATE tasks SET done = 1 WHERE id = ?", (task_id,))

def list_open_tasks(conn):
    cursor = conn.execute(
        "SELECT id, title, priority, due_date FROM tasks WHERE done = 0 ORDER BY due_date"
    )
    return cursor.fetchall()

def save_snapshot(conn, value):
    with conn:
        conn.execute(
            "INSERT INTO snapshots (fetched_at, value) VALUES (?, ?)",
            (datetime.now().isoformat(timespec="minutes"), value),
        )

def build_report(conn):
    tasks = list_open_tasks(conn)
    cursor = conn.execute("SELECT fetched_at, value FROM snapshots ORDER BY id DESC LIMIT 1")
    latest = cursor.fetchone()

    lines = [f"PulseOps report — {datetime.now().strftime('%Y-%m-%d')}", ""]
    lines.append(f"Open tasks: {len(tasks)}")
    for task_id, title, priority, due_date in tasks:
        lines.append(f"  [{priority}] {title} (due {due_date})")
    if latest:
        lines.append(f"\nLatest snapshot: {latest[1]} (fetched {latest[0]})")
    else:
        lines.append("\nNo snapshots fetched yet.")
    return "\n".join(lines)

Security review
  • All SQL uses ? placeholders — verified across every function in database.py and services.py.
  • The API URL and any API key come from config.py, sourced from environment variables — never hard-coded, never logged.
  • Every external request has an explicit timeout, preventing an unresponsive API from hanging the whole application.
  • No subprocess or shell=True usage anywhere in this project — the attack surface for command injection is zero.
  • The database file path is read from configuration, not accepted as unchecked user input, avoiding any path-traversal concern.
Performance considerations

SQLite comfortably handles the scale of a personal tool like this (thousands of tasks/snapshots) with no special tuning. If list_open_tasks were ever called extremely frequently against a much larger dataset, an index on (done, due_date) would be the first optimization to consider — introduced only if profiling actually shows it's needed, not preemptively.

Reference

Standard library field guide

Twenty modules you'll reach for constantly. Each entry: purpose, when to use it, a minimal example, and a common mistake.

os

Purpose: Operating-system interfaces — environment variables, process info, low-level path operations.

Common: os.environ, os.getcwd(), os.listdir()

When to use: Reading environment variables and config. For paths, prefer pathlib (below) for new code.

import os
api_key = os.environ.get("API_KEY", "")

Mistake: os.environ["KEY"] raises KeyError if unset — use .get() with a default.

sys

Purpose: Interpreter-level operations — command-line arguments, exiting with a status code, module search path.

Common: sys.argv, sys.exit(), sys.path

When to use: Quick scripts needing raw CLI args (prefer argparse for anything beyond one or two positional args).

import sys
if len(sys.argv) < 2:
    sys.exit("Usage: script.py <filename>")

Real-world use: Exiting a script with a specific error code for shell scripts/CI pipelines to detect failure.

pathlib

Purpose: Modern, cross-platform, object-oriented filesystem paths (see Level 05.2).

Common: Path(), .exists(), .glob(), .mkdir(), / for joining

from pathlib import Path
Path("data/reports").mkdir(parents=True, exist_ok=True)

Mistake: Mixing os.path string operations with pathlib objects inconsistently across one project — pick one, prefer pathlib for new code.

subprocess

Purpose: Run external programs and capture their output (see Level 07.9).

Common: subprocess.run(args_list, capture_output=True, text=True, timeout=...)

import subprocess
result = subprocess.run(["git", "status"], capture_output=True, text=True)

Mistake: shell=True with untrusted input — command injection risk. Pass arguments as a list instead.

shutil

Purpose: High-level file operations — copying, moving, deleting whole trees, disk usage.

Common: shutil.copy(), shutil.rmtree(), shutil.disk_usage()

import shutil
total, used, free = shutil.disk_usage("/")

Mistake: shutil.rmtree() deletes recursively with no confirmation and no undo — double-check the path before calling it.

json

Purpose: Convert between Python objects and JSON text (see Level 07.1).

Common: json.dumps(), json.loads(), json.dump(), json.load()

import json
text = json.dumps({"key": "value"}, indent=2)

Mistake: Trying to serialize non-JSON-native types (datetime, sets, custom objects) directly — convert first.

csv

Purpose: Correctly read/write comma-separated tabular data (see Level 07.2).

Common: csv.reader, csv.writer, csv.DictReader, csv.DictWriter

import csv
with open("data.csv", newline="") as f:
    rows = list(csv.DictReader(f))

Mistake: Omitting newline="" when opening the file on Windows — can introduce blank rows.

re

Purpose: Pattern matching in text (see Level 07.3).

Common: re.search(), re.findall(), re.sub(), re.compile()

import re
digits = re.findall(r"\d+", "Order 42, 3 items")

Mistake: Not using raw strings (r"...") for patterns containing backslashes.

datetime

Purpose: Represent and manipulate dates/times (see Level 07.4).

Common: datetime.now(), timedelta, .strftime(), .strptime()

from datetime import datetime
print(datetime.now().strftime("%Y-%m-%d"))

Mistake: Mixing naive and timezone-aware datetimes in comparisons.

math

Purpose: Mathematical functions beyond basic operators — trigonometry, logarithms, constants.

Common: math.sqrt(), math.floor(), math.ceil(), math.pi

import math
print(math.sqrt(2))

Real-world use: Geometry, distance calculations, anything needing more than + - * / **.

statistics

Purpose: Common statistical calculations without needing a third-party numerical library.

Common: mean(), median(), stdev()

import statistics
print(statistics.mean([4, 8, 15, 16, 23, 42]))

When to use: Small-to-medium datasets in plain Python; reach for a dedicated library (outside this course's scope) for large-scale numerical work.

random

Purpose: Pseudo-random number generation — not cryptographically secure.

Common: random.randint(), random.choice(), random.shuffle()

import random
print(random.choice(["heads", "tails"]))

Mistake: Using random for security-sensitive values (tokens, password reset codes) — use secrets instead for anything security-related.

collections

Purpose: Specialized container types (see Level 06.9).

Common: Counter, defaultdict, namedtuple, deque

from collections import Counter
Counter("mississippi").most_common(1)

Real-world use: deque for an efficient sliding window or queue — much faster than a list for repeated additions/removals at both ends.

itertools

Purpose: Fast, memory-efficient tools for working with iterators.

Common: chain(), combinations(), permutations(), groupby()

from itertools import combinations
list(combinations([1, 2, 3], 2))

When to use: Combinatorics, flattening nested iterables, and any lazy-sequence processing where memory matters.

functools

Purpose: Tools for working with functions themselves (see Level 06.5, 06.10).

Common: wraps(), lru_cache(), reduce(), partial()

from functools import lru_cache

@lru_cache(maxsize=None)
def fib(n):
    return n if n < 2 else fib(n-1) + fib(n-2)

Mistake: Writing a decorator without @wraps, which hides the original function's name/docstring.

typing

Purpose: Support for type hints beyond built-in generics (see Level 06.7).

Common: Optional, Union, Callable, Any

from typing import Optional
def find(x: int) -> Optional[str]: ...

Real-world use: Documenting a function that might return None, making that possibility explicit to callers and type checkers.

logging

Purpose: Structured, leveled diagnostic output for production code (see Level 08.5).

Common: basicConfig(), getLogger(), .info(), .warning(), .error()

import logging
logging.basicConfig(level=logging.INFO)
logging.getLogger(__name__).info("started")

Mistake: Logging secrets or sensitive personal data in plaintext.

argparse

Purpose: Build proper command-line interfaces with help text, types, and validation for free.

Common: ArgumentParser(), add_argument(), parse_args()

import argparse
parser = argparse.ArgumentParser()
parser.add_argument("--verbose", action="store_true")
args = parser.parse_args()

Real-world use: Any script meant to be run repeatedly with different options, rather than hard-coded values.

sqlite3

Purpose: A file-based relational database, built in — no server or installation needed (see Level 07.7–07.8).

Common: connect(), execute(), fetchall(), commit()

import sqlite3
conn = sqlite3.connect("app.db")
conn.execute("SELECT * FROM users WHERE id = ?", (1,))

Mistake: Building SQL with string formatting instead of ? placeholders — SQL injection risk.

threading / multiprocessing

Purpose: Concurrent execution — threads for I/O-bound work, processes for CPU-bound work (see Level 09.1).

Common: Thread(), Process(), .start(), .join()

from threading import Thread
t = Thread(target=download_file, args=(url,))
t.start()

Mistake: Expecting threading to speed up CPU-bound work — the GIL prevents true parallel Python execution across threads.

asyncio

Purpose: Single-threaded, cooperative concurrency for I/O-bound work (see Level 09.2).

Common: async def, await, asyncio.run(), asyncio.gather()

import asyncio
async def main():
    await asyncio.sleep(1)
asyncio.run(main())

Mistake: Calling a blocking (non-async) function inside a coroutine — it freezes the entire event loop.

unittest

Purpose: Class-based, built-in testing framework (see Level 08.1). pytest is the more common third-party alternative for new projects.

Common: TestCase, assertEqual(), assertRaises()

import unittest
class T(unittest.TestCase):
    def test_x(self):
        self.assertEqual(1 + 1, 2)

Real-world use: Codebases that specifically avoid third-party test dependencies, or legacy projects already built on it.
