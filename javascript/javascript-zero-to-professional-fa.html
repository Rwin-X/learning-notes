جاوااسکریپت چیست و ECMAScript چیست؟مفهوم

جاوااسکریپت یک زبان برنامه‌نویسی است. ECMAScript مشخصاتِ (Specification) آن است — استانداردی مکتوب که گروهی به نام TC39 نگهداری می‌کند و دقیقاً تعریف می‌کند زبان باید چگونه رفتار کند. هر موتور جاوااسکریپت (V8 در کروم و Node.js، SpiderMonkey در فایرفاکس، JavaScriptCore در سافاری) پیاده‌سازیِ مستقلی از همین مشخصات است.

این موضوع عملاً مهم است: وقتی «ES2020» یا «ES6» می‌خوانید، منظور یک نسخهٔ سالانه از مشخصات ECMAScript است، نه زبانی جدا. سینتکس‌هایی که بعداً یاد می‌گیرید — let، توابع پیکانی، کلاس‌ها و async/await — همگی قابلیت‌های ECMAScript هستند که موتورها به‌مرور پیاده‌سازی می‌کنند. اگر قابلیتی کار نکرد، معمولاً دلیلش این است که موتورِ اجراکنندهٔ کد شما قدیمی‌تر از نسخه‌ای از مشخصات است که آن را معرفی کرده — نه اینکه «جاوااسکریپت» و «ECMAScript» با هم اختلاف داشته باشند.

مدل ذهنی
مشخصات ECMAScript← پیاده‌سازی می‌شود توسط ←یک موتور (V8، SpiderMonkey، …)←کد جاوااسکریپت شما را اجرا می‌کند
چرا اسم «JavaScript»؟این زبان در سال ۱۹۹۵ در Netscape ساخته شد و نامی گرفت که به‌دلیل بازاریابی از محبوبیت Java وام می‌گرفت. جدا از شباهت سطحی سینتکس به خانوادهٔ زبان‌های C، جاوااسکریپت و جاوا دو زبان بی‌ارتباط با طراحان، معناشناسی و کاربردهای متفاوت‌اند.
تمرین: لایه را تشخیص دهید

برای هر مورد مشخص کنید بخشی از زبان ECMAScript است یا چیز دیگری: Array.prototype.map · document.querySelector · async/await · ماژول fs در Node.

نمایش پاسخ

Array.prototype.map و async/await هستهٔ ECMAScript‌اند — در یک تب مرورگر و در Node.js دقیقاً یکسان کار می‌کنند و به HTML یا فایل‌سیستم نیازی ندارند. document.querySelector یک API مرورگر (DOM) است، نه خود جاوااسکریپت — در Node.js اصلاً document وجود ندارد. ماژول fs در Node یک API میزبانِ Node.js است — در مرورگر وجود ندارد.

موتور، محیط اجرا و میزبان: مرورگر در برابر Node.jsمفهوم

یک موتور (مثل V8) فقط می‌داند ECMAScript را اجرا کند: متغیرها، توابع، شیءها، ریاضیات و کار با رشته‌ها. نمی‌داند صفحهٔ وب یا فایل‌سیستم چیست. یک محیط میزبان (Host) آن موتور را در خود جا می‌دهد و اشیای اضافه‌ای برای کار در اختیارش می‌گذارد:

  • مرورگر یک موتور را در خود دارد و window، document، fetch، localStorage و رویدادهای DOM را اضافه می‌کند.
  • Node.js همان موتور V8 کروم را در خود دارد، اما به‌جای آن‌ها دسترسی به فایل‌سیستم، process و بارگذاری ماژول را اضافه می‌کند — بدون هیچ documentی.

موتور + اشیای اضافه‌ای که میزبان می‌دهد + سازوکار زمان‌بندی که کد ناهمگام را پیش می‌برد، روی هم معمولاً محیط اجرا (Runtime) نامیده می‌شود. برای همین «جاوااسکریپت هرجا اجرا می‌شود» دربارهٔ خودِ زبان درست است، ولی اسکریپتی که برای مرورگر نوشته شده (و از document استفاده می‌کند) در Node.js بلافاصله خطا می‌دهد و برعکس.

کنسول مرورگر
console.log(typeof window);     // "object"  — exists in the browser
console.log(typeof document);   // "object"  — exists in the browser
console.log(typeof process);    // "undefined" — this is a Node.js global
←این کد را در DevTools کروم/فایرفاکس اجرا کنید — process تعریف‌نشده است چون یک شیء میزبانِ مخصوص Node.js است.
اشتباه رایجکپی‌کردن کد یک آموزش مرورگر داخل اسکریپت Node.js (یا برعکس) و فرض‌کردن اینکه «همه‌اش جاوااسکریپت است، پس کار می‌کند». زبان مشترک است؛ اشیای پیرامونش مشترک نیستند.
اجرای جاوااسکریپت: کنسول، اسکریپت درون‌خطی و فایل خارجیمفهوم

سه جای رایج برای اجرای جاوااسکریپت هنگام یادگیری وجود دارد و کدهای این دوره همیشه می‌گویند کدام را انتظار دارند:

کنسول مرورگر

DevTools را باز کنید (F12 یا کلیک راست ← Inspect ← Console) و کد را مستقیم تایپ کنید. برای آزمایش سریع عالی است؛ چیزی ذخیره نمی‌شود.

فایل اسکریپت خارجی
index.html
<!doctype html>
<html>
  <body>
    <h1>Hello</h1>
    <script src="script.js" defer></script>
  </body>
</html>

ویژگی defer به مرورگر می‌گوید اسکریپت را در پس‌زمینه دانلود کند، اما فقط پس از تمام‌شدن تجزیهٔ HTML اجرا کند — روش استانداردِ بارگذاری اسکریپت‌هایی که به محتوای صفحه دست می‌زنند.

اسکریپت درون‌خطی
index.html
<script>
  console.log("Running directly inside the page");
</script>

کار می‌کند، اما ساختار (HTML) و رفتار (جاوااسکریپت) را در یک فایل قاطی می‌کند — برای یک دمو پنج‌خطی مشکلی ندارد، در پروژه‌های واقعی پرهیز می‌شود.

دستور (Statement)، عبارت (Expression) و سینتکسمفهوم

عبارت هر تکه کدی است که یک مقدار تولید می‌کند: 2 + 2، "hi".length، true. دستور یک فرمان کامل است — ممکن است شامل عبارت‌ها باشد، اما خودش مقداری تولید نمی‌کند که جای دیگری استفاده کنید: یک بلوک if، یک حلقه، یک تعریف متغیر.

محک عملی: می‌توانید آن را سمت راست یک انتساب بگذارید؟ const x = (2 + 2) کار می‌کند — عبارت است. const x = (if (true) {}) خطای سینتکس است — if دستور است، نه عبارتِ مقداردهنده.

script.js
3 + 4;              // expression statement — evaluates to 7, value is discarded
const total = 3 + 4; // statement, containing the expression "3 + 4"
true ? "yes" : "no"; // the ternary IS an expression — it can be assigned

دستورهای جاوااسکریپت معمولاً با نقطه‌ویرگول تمام می‌شوند. موتور اغلب می‌تواند نقطه‌ویرگول‌های جاافتاده را خودکار درج کند (رفتاری به نام Automatic Semicolon Insertion یا ASI)، برای همین کد مبتدی گاهی «بدون آن‌ها هم کار می‌کند» — اما ASI لبه‌های تیزی دارد که در تمرین پایین می‌بینید، برای همین این دوره نقطه‌ویرگول‌ها را صریح می‌نویسد.

پیش‌بینی خروجی — درج خودکار نقطه‌ویرگول
function getValue() {
  return
    { value: 42 };
}

console.log(getValue());
نمایش پاسخ

خروجی: undefined — نه شیء.

ASI شکستن خط بلافاصله بعد از return را پایان دستور حساب می‌کند؛ پس موتور در واقع return; اجرا می‌کند و بعدش یک شیء لیترال دست‌نیافتنی می‌ماند. این پرنقل‌قول‌ترین باگ واقعیِ مربوط به ASI است. راه‌حل: مقدار بازگشتی را همیشه در همان خطِ return بنویسید، یا داخل پرانتز بگذارید.

کامنت‌ها، قالب‌بندی و «حالت سخت‌گیرانه» (strict mode)مفهوم
script.js
// A single-line comment — ignored by the engine

/*
  A block comment.
  Useful for longer explanations.
*/

"use strict";
// Enables strict mode for the rest of this file (or function).

حالت strict یک حالت اختیاری است که جاوااسکریپت را در برابر اشتباه‌هایی سخت‌گیرتر می‌کند که در حالت عادی بی‌صدا اجازه می‌دهد — مثلاً انتساب به متغیرِ تعریف‌نشده به‌جای ساختن بی‌سروصدای یک متغیر سراسری، خطا می‌دهد. کد داخل ماژول‌های ES و داخل کلاس‌ها خودکار strict است؛ اسکریپت‌های ساده نیستند، مگر اینکه "use strict"; را بالای فایل بنویسید.

script.js
"use strict";
mistypedVarName = 5;
// ReferenceError: mistypedVarName is not defined

// Without "use strict", the line above would silently
// create a global variable instead of failing loudly.

سناریوی اشکال‌زدایی

«وقتی صفحه را باز می‌کنم script.js هیچ کاری نمی‌کند»اشکال‌زدایی
علائمصفحه لود می‌شود، اما اسکریپتی که باید در کنسول چیزی چاپ کند یا صفحه را تغییر دهد هیچ نتیجه‌ای ندارد و خطای قرمزی هم دیده نمی‌شود.
مشاهدهDevTools ← Console را باز کنید. اگر واقعاً خالی است و هیچ خطایی نیست، احتمالاً اسکریپت اصلاً اجرا نشده؛ اگر خطای قرمز هست، مشکل دیگری (معمولاً ساده‌تر) است.
فرضیهمسیر src تگ <script> اشتباه است، یا نسبت به فایل HTML، فایل در مسیر نوشته‌شده وجود ندارد.
آزمایشDevTools ← تب Network را باز کنید، صفحه را reload کنید و دنبال script.js در فهرست درخواست‌ها بگردید. وضعیت 404 یعنی مسیر نادرست است.
علت ریشه‌ایمسیرهای src="..." نسبت به محل فایل HTML هستند، نه ریشهٔ پروژه یا پوشه‌ای که ویرایشگر باز کرده — ناهماهنگی رایج وقتی فایل‌ها در زیرپوشه‌اند.
رفعمسیر نسبی را درست کنید (مثلاً src="./js/script.js")، یا فایل را مطابق مسیر نوشته‌شده جابه‌جا کنید.
راستی‌آزماییصفحه را reload کنید؛ تب Network باید script.js را با وضعیت 200 نشان دهد و خروجی console.log شما ظاهر شود.

مینی‌پروژه — کارت معرفی در کنسولمقدماتی

یک index.html با script.js پیوندخورده و defer بسازید. در script.js، فقط با کامنت و فراخوانی‌های console.log و الحاق رشته (+) — هنوز متغیر نداریم، آن سطح ۰۲ است — یک «کارت معرفی» پنج‌خطی در کنسول چاپ کنید: نام، نقش، دو واقعیت و یک جملهٔ پایانی. بالای هر خط یک کامنت بنویسید که توضیح دهد چه چیزی چاپ می‌کند. در DevTools بررسی کنید، سپس همان خطوط را مستقیم در کنسول paste کنید تا مطمئن شوید یکسان رفتار می‌کنند.

چالش پایانی

چالش پایانی — پنج خط کد را دسته‌بندی کنیدچالش

برای هر خط بگویید دستور است، عبارت است، یا بسته به زمینه هر دو — و اینکه به هستهٔ جاوااسکریپت تعلق دارد یا محیط میزبان: 2 + 2، if (x) {}، document.title، "use strict";، fetch("/api").

نمایش پاسخ

2 + 2 — عبارت. if (x) {} — دستور (کنترل جریان، هیچ‌وقت مقدار نیست). document.title — عبارت، و API میزبان (DOM مرورگر) است نه هستهٔ جاوااسکریپت. "use strict"; — یک دستورِ خاص (directive prologue). fetch("/api") — عبارت (فراخوانی تابعی که Promise برمی‌گرداند) و آن هم API میزبان است نه هستهٔ جاوااسکریپت.

متغیر، نامی است که به یک مقدار گره می‌خورد (binding). جاوااسکریپت سه کلیدواژهٔ تعریف دارد و آن‌ها سلیقه‌ایِ قابل‌جایگزینی نیستند — قواعد حوزهٔ (scope) متفاوتی دارند.

script.js

پیش‌فرضتان const باشد. فقط وقتی سراغ let بروید که بدانید binding باید تغییر کند (شمارندهٔ حلقه، انباشتگر). var را فقط برای خواندن کد قدیمی نگه دارید — حوزهٔ آن تابع است نه بلوک، یعنی از بلوک‌های if/for بیرون می‌زند و باگ‌های واقعی می‌سازد، و با مقدار اولیهٔ undefined hoist می‌شود، به‌جای اینکه پیش از تعریف واقعاً غیرقابل‌دسترس باشد.

const یعنی «تغییرناپذیر» نیستیعنی خودِ binding نمی‌تواند دوباره انتساب شود — نام متغیر را نمی‌شود به مقدار دیگری اشاره داد. اگر آن مقدار شیء یا آرایه باشد، محتویاتش همچنان قابل تغییر است: const arr = [1]; arr.push(2); کاملاً مجاز است.

تبدیل نوع (Coercion)، truthy و falsyمفهوم

Coercion یعنی جاوااسکریپت مقداری را از یک نوع به نوع دیگر تبدیل کند. تبدیل صریح تبدیلی است که عمداً می‌نویسید (String(42)، Number("42")، Boolean(0)). تبدیل ضمنی وقتی خودکار رخ می‌دهد که عملگر عملوندهایی با نوع‌های ناهمخوان بگیرد.

دقیقاً هفت مقدار falsy هستند — هنگام تبدیل به boolean برابر false می‌شوند: false، 0، -0، ""، null، undefined و NaN. هر مقدار دیگر truthy است، از جمله "0" (رشتهٔ غیرخالی)، [] و {}.

دموی زنده — زمین‌بازی تبدیل نوعدر همین صفحه اجرا می‌شود
یک عبارت را انتخاب کنید و «محاسبه» را بزنید.
برابری: == در برابر ===مفهوم

=== («برابری سخت‌گیرانه») نوع و مقدار را بدون هیچ تبدیلی مقایسه می‌کند. == («برابری سهل‌گیرانه») ابتدا عملوندها را به نوع هماهنگ تبدیل می‌کند، طبق قواعدی که به‌راحتی اشتباه به خاطر سپرده می‌شوند. قرارداد حرفه‌ای: همیشه از === و !== استفاده کنید، با دقیقاً یک استثنای رایج.

script.js
value === null            // strict check for null only
value == null             // true for BOTH null and undefined — the one
                           // widely-accepted, intentional use of `==`

'5' === 5   // false — different types, no coercion
'5' == 5    // true  — '5' is coerced to a number first
عملگرها: حسابی، منطقی، سه‌تایی، nullish coalescing، optional chainingمفهوم

سه روش نوشتن تابعمفهوم
script.js
// 1. Function declaration — hoisted: usable before its definition
function add(a, b) {
  return a + b;
}

// 2. Function expression — a function assigned to a variable,
//    NOT hoisted in a usable way (the variable is, the value isn't)
const subtract = function (a, b) {
  return a - b;
};

// 3. Arrow function — shorter syntax, and no own `this` (see Level 05)
const multiply = (a, b) => a * b;          // implicit return

  console.log("adding", a, b);
  return a + b;
};

تعریف‌های تابع (Function Declaration) همراه با بدنهٔ کامل hoist می‌شوند، پس می‌توان آن‌ها را زودتر از جایی که در فایل نوشته شده‌اند فراخواند. عبارت‌های تابع (از جمله توابع پیکانی) فقط بعد از خطی که تعریفشان می‌کند قابل‌استفاده‌اند — فراخوانی زودتر همان خطایی را می‌دهد که از hoistشدن const/let انتظار دارید.

اشتباه رایجتوابع پیکانی صرفاً «تابع کوتاه‌تر» نیستند. عمداً this مخصوص خودشان را bind نمی‌کنند، شیء arguments ندارند و با new به‌عنوان سازنده قابل‌استفاده نیستند. وقتی به هر کدام از این‌ها نیاز دارید سراغ function معمولی بروید؛ توابع پیکانی معمولاً برای کال‌بک‌های کوتاه مناسب‌اند.
پارامترها: پیش‌فرض، rest و spreadمفهوم
script.js
// Default parameter — used only when the argument is undefined
function greet(name = "friend") {
  return `Hello, ${name}!`;
}
greet();          // "Hello, friend!"
greet(undefined); // "Hello, friend!"
greet(null);      // "Hello, null!" — null is a real value, default is skipped

// Rest parameter — gathers remaining arguments into a real array
function sum(...numbers) {
  return numbers.reduce((total, n) => total + n, 0);
}
sum(1, 2, 3, 4); // 10

// Spread — the opposite direction: expand an array into arguments
const nums = [4, 9, 16];
Math.max(...nums); // 16

rest و spread سینتکس یکسانِ ... دارند اما بسته به موقعیت کار معکوس انجام می‌دهند: در فهرست پارامترها ... مقادیر را جمع می‌کند؛ در فراخوانی تابع یا لیترال آرایه/شیء ... آن‌ها را باز می‌کند. سطح ۰۴ دوباره سراغ spread برای کپی آرایه‌ها و شیءها می‌رود.

کال‌بک‌ها و توابع مرتبهٔ بالاترمفهوم

در جاوااسکریپت توابع مقدار هستند — می‌شود آن‌ها را در متغیر ذخیره، به‌عنوان آرگومان پاس داد و از توابع دیگر برگرداند. تابعی که تابع دیگری را بگیرد یا برگرداند تابع مرتبهٔ بالاتر (higher-order) نام دارد؛ تابعی که پاس داده می‌شود تا بعداً فراخوانی شود کال‌بک (callback) است.

script.js
function processOrder(item, onComplete) {
  console.log(`Processing ${item}...`);
  onComplete(item);          // "onComplete" is a callback
}

processOrder("book", (item) => {
  console.log(`${item} shipped!`);
});
// Processing book...
// book shipped!

// A higher-order function that RETURNS a function:
function multiplyBy(factor) {
  return (n) => n * factor;
}
const double = multiplyBy(2);
double(5); // 10

این الگو پایهٔ متدهای آرایه مثل map/filter (سطح ۰۴)، هندلرهای رویداد DOM (سطح ۰۶) و Promiseها (سطح ۰۷) است — همگی در اصل یعنی «تابعی بده تا بعداً صدا زده شود».

حوزه: سراسری، تابعی، بلوکی و لغویمفهوم

حوزه (Scope) محدوده‌ای از کد است که در آن یک نام متغیر دیده می‌شود. let/const حوزهٔ بلوکی دارند — محدود به نزدیک‌ترین { }. حوزهٔ لغوی (Lexical Scope) یعنی دید متغیرها بر اساس محل فیزیکی نوشته‌شدن کد تعیین می‌شود، نه اینکه کدام تابع آن را صدا زده — یک تابع درونی همیشه می‌تواند متغیرهای تابع(های) بیرونی‌ای را ببیند که داخلشان نوشته شده.

بستار (Closure): توابعی که به یاد می‌آورندمفهوم

بستار چیزی است که وقتی به دست می‌آید که یک تابع درونی داخل یک تابع بیرونی ساخته شود و آن تابع درونی پس از پایان اجرای تابع بیرونی هم استفاده شود — اما همچنان بتواند متغیرهای تابع بیرونی را بخواند و به‌روز کند. متغیرها کپی نمی‌شوند؛ تابع درونی یک ارجاع زنده به محیط لغوی واقعیِ تابع بیرونی نگه می‌دارد، و آن محیط دقیقاً به این دلیل در حافظه زنده می‌ماند که چیزی هنوز به آن ارجاع می‌دهد.

هر دکمهٔ زیر شمارندهٔ خودش را صدا می‌زند که با یک فراخوانی جداگانه از makeCounter() ساخته شده. ببینید هیچ‌وقت در کار هم دخالت نمی‌کنند — این همان بستاری است که وضعیت خصوصی را نگه می‌دارد.

اشتباه رایجساختن بستار داخل حلقه با var باگی کلاسیک است: همهٔ بستارها یک var تابع‌محدود را به اشتراک می‌گذارند، پس همه «مقدار نهایی» آن را به یاد می‌آورند. استفاده از let مشکل را حل می‌کند، چون let برای هر تکرار حلقه یک binding تازه می‌سازد.

بازگشت (Recursion)مفهوم

تابع بازگشتی خودش را فراخوانی می‌کند و به سمت یک حالت پایه (base case) حرکت می‌کند — شرطی که بازگشت را متوقف می‌کند. بدون آن، بازگشتِ بی‌پایان رخ می‌دهد و RangeError: Maximum call stack size exceeded پرتاب می‌شود (پشتهٔ فراخوانی در سطح ۰۶ مفصل بررسی می‌شود).

script.js
function factorial(n) {
  if (n <= 1) return 1;        // base case
  return n * factorial(n - 1); // recursive case, moving toward the base case
}
factorial(5); // 120

function countdown(n) {
  if (n < 0) return;           // base case
  console.log(n);
  countdown(n - 1);
}
countdown(3); // 3, 2, 1, 0

بازگشت خودبه‌خود بهتر از حلقه نیست — برای مسائلی که ذاتاً خودمتشابه‌اند (پیمایش درخت، داده‌های تودرتو، الگوریتم‌های تقسیم‌وحل) مناسب‌تر است. برای شمارش ساده، حلقه معمولاً شفاف‌تر است و اصلاً رشد پشتهٔ فراخوانی ندارد.

چالش پایانی

چالش پایانی — یک wrapper به نام once بسازیدچالش

تابع مرتبهٔ بالاتر once(fn) را بنویسید که تابع جدیدی برگرداند؛ این تابع بار اول fn را صدا می‌زند، و در هر فراخوانی بعدی همان نتیجهٔ اول را بدون صدازدن دوبارهٔ fn برمی‌گرداند. برای ردیابی اینکه قبلاً اجرا شده یا نه از بستار استفاده کنید.

نمایش پاسخ
function once(fn) {
  let called = false;
  let result;
  return function (...args) {
    if (!called) {
      result = fn(...args);
      called = true;
    }
    return result;
  };
}

script.js

  constructor(name) {
    this.name = name;
  }
  speak() {
    return `${this.name} makes a sound.`;

  constructor(name, breed) {
    super(name);       // MUST run before using "this" — calls Animal's constructor
    this.breed = breed;

    return `${this.name} barks. (${super.speak()})`;
    // super.speak() explicitly calls the PARENT's version too
  }
}

وراثت را فقط برای رابطه‌های واقعیِ «است-یک» (is-a) به کار ببرید. برای رابطه‌های «دارد-یک» (has-a) (یک ماشین موتور دارد، موتور نیست)، ترکیب (composition) — ساختن شیءها از قطعات کوچک‌تر کنار هم — معمولاً انعطاف‌پذیرتر است و الگوی ترجیحی جاوااسکریپت مدرن است.

کلیدواژهٔ this، درست توضیح داده‌شدهمفهوم

this با محلِ تعریف تابع ثابت نمی‌شود — به‌جز یک استثنای بزرگ (توابع پیکانی) — بلکه با نحوهٔ فراخوانی تابع تعیین می‌شود. چهار الگوی فراخوانی وجود دارد:

script.js
const obj = {
  name: "Widget",
  show() { console.log(this.name); },
};

// 1. Method call — "this" is the object before the dot
obj.show(); // "Widget"

// 2. Plain function call — "this" is undefined in strict mode
//    (or the global object in non-strict, sloppy mode)
const detached = obj.show;
detached(); // TypeError: Cannot read properties of undefined
            // because "this" is undefined, not "obj"

// 3. Constructor call with "new" — "this" is the new instance
function Point(x) { this.x = x; }
const p = new Point(5); // this === p

// 4. Explicit binding — call/apply/bind FORCE what "this" means
function greet() { return `Hi, ${this.name}`; }
greet.call({ name: "Zed" });     // "Hi, Zed" — calls immediately
greet.apply({ name: "Zed" });    // same as .call, args passed as an array
const bound = greet.bind({ name: "Zed" }); // returns a new function,
bound();                                    // permanently bound — "Hi, Zed"

// Arrow functions have NO "this" of their own — they use whatever
// "this" was in the surrounding scope when they were DEFINED.
const arrowObj = {
  name: "Widget",
  show: () => console.log(this?.name), // "this" here is NOT arrowObj
};
arrowObj.show(); // undefined — inherited the outer (module/global) this
اشتباه رایجپاس‌دادن یک متد به‌عنوان کال‌بک، bind آن را از بین می‌برد: button.addEventListener("click", obj.show) متد show را مثل تابع ساده صدا می‌زند و obj را به‌عنوان this از دست می‌دهد. راه‌حل: obj.show.bind(obj) یا بستن آن در یک تابع: () => obj.show().
پیش‌بینی خروجی — this داخل متد معمولی در برابر پیکانی
const timer = {
  seconds: 0,
  startRegular() {
    setInterval(function () {
      this.seconds++;          // regular function — new "this" each call
      console.log(this.seconds);
    }, 1000);
  },
  startArrow() {
    setInterval(() => {
      this.seconds++;          // arrow — keeps startArrow's "this"
      console.log(this.seconds);
    }, 1000);
  },
};
نمایش پاسخ

startRegular() مرتب NaN لاگ می‌کند (یا در حالت strict خطا می‌دهد) — تابع ساده‌ای که به setInterval پاس داده شده با this برابر شیء سراسری (یا undefined) صدا زده می‌شود، نه timer. startArrow() درست 1, 2, 3... لاگ می‌کند چون تابع پیکانی this را از بافتِ فراخوانیِ متدِ startArrow می‌گیرد که در آن this === timer. این رایج‌ترین دلیل است که توسعه‌دهندگان داخل کال‌بک‌هایی که به this یک شیء نیاز دارند سراغ توابع پیکانی می‌روند.

توابع خالص (Pure) و تغییرناپذیریمفهوم

تابع خالص همیشه برای ورودی یکسان خروجی یکسان برمی‌گرداند و هیچ اثر جانبی مشاهده‌پذیری ندارد (آرگومان‌ها را تغییر نمی‌دهد، به DOM دست نمی‌زند، فراخوانی شبکه ندارد، به وضعیت قابل‌تغییر بیرونی تکیه نمی‌کند). توابع خالص به‌سادگی قابل‌پیش‌بینی‌اند، جداگانه قابل‌تست‌اند (سطح ۰۸) و اجرای چندبارهٔ آن‌ها بی‌خطر است.

script.js
// Impure — mutates its argument, a side effect
function addItemImpure(cart, item) {
  cart.push(item);
  return cart;
}

// Pure — same inputs always produce the same new output,
// original is left completely untouched
function addItemPure(cart, item) {
  return [...cart, item];
}

برنامه‌های واقعی نمی‌توانند ۱۰۰٪ خالص باشند — در نهایت چیزی باید روی صفحه رندر یا داده ذخیره شود — اما محدودکردن اثرهای جانبی به یک لایهٔ نازکِ بیرونی و خالص نگه‌داشتن منطق هسته، رویه‌ای حرفه‌ای و پرکاربرد است که مستقیماً در بخش تست سطح ۰۸ نتیجه می‌دهد.

تجزیه، زمینه‌های اجرا (Execution Context) و پشتهٔ فراخوانیمفهوم

پیش از اجرای هرچیز، موتور کد شما را تجزیه (parse) می‌کند تا ساختاری قابل‌اجرا بسازد و در همان حین خطاهای سینتکس را بررسی کند. بعد کد را داخل زمینه‌های اجرا (execution context) اجرا می‌کند — یکی برای حوزهٔ سراسری ساخته می‌شود و یکی جدید برای هر فراخوانی تابع، که متغیرهای محلی همان فراخوانی و محیط لغوی خودش را نگه می‌دارد (سازوکار واقعیِ قواعد حوزه در سطح ۰۳).

زمینه‌های اجرا روی پشتهٔ فراخوانی (call stack) ردیابی می‌شوند — ساختاری آخرین‌ورودی-اولین‌خروجی. فراخوانی تابع یک زمینهٔ جدید روی آن push می‌کند؛ برگشت از تابع آن زمینه را pop می‌کند.

پشتهٔ فراخوانی — برای زنجیره‌ای از سه فراخوانی تابع
main()callsfirst()callssecond()callsthird()

پشته، از بالا به پایین، هنگامی که third() در حال اجراست: third() ← second() ← first() ← main(). هرکدام به ترتیب معکوسِ push شدن برمی‌گردد و pop می‌شود — دقیقاً به همین دلیل ردپای پشته (که در DevTools از بالا به پایین خوانده می‌شود) ابتدا درونی‌ترین فراخوانیِ خطادار و بعد همهٔ فراخواننده‌های آن را نشان می‌دهد.

script.js
function third() { throw new Error("boom"); }
function second() { third(); }
function first() { second(); }
first();

// Uncaught Error: boom
//   at third   (script.js:1)
//   at second  (script.js:2)
//   at first   (script.js:3)
//   at script.js:4      ← read top-down: where it broke, then who called it

تابعی که خودش را (یا چرخه‌ای از توابع که یکدیگر را) بدون حالت پایه فراخوانی کند، مدام زمینهٔ جدید push می‌کند تا به حد ثابت اندازهٔ پشته برسد و RangeError: Maximum call stack size exceeded پرتاب شود — پیامد زمان اجرایی اشتباه بازگشتی که در سطح ۰۳ معرفی شد.

حافظه: heap و زباله‌روب (Garbage Collection)مفهوم

مقادیر اولیه معمولاً مستقیم روی پشتهٔ فراخوانی زندگی می‌کنند: اندازه‌دار و کوتاه‌عمر. شیءها، آرایه‌ها و توابع در ناحیهٔ جداگانه و بزرگ‌تری از حافظه به نام heap تخصیص می‌یابند — برای همین متغیری که شیء را «نگه می‌دارد» در واقع ارجاعی (سطح ۰۴) به داخل heap دارد. وقتی هیچ ارجاع قابل‌دسترسی به یک شیء heap در هیچ‌جا باقی نمی‌ماند (نه روی پشته، نه داخل شیء قابل‌دسترسی دیگر، نه در بستار زنده)، زباله‌روبِ موتور آن حافظه را خودکار آزاد می‌کند — در جاوااسکریپت هیچ‌وقت خودتان free() صدا نمی‌زنید.

چرا این در عمل مهم استبستار (سطح ۰۳) متغیرهای بیرونی‌اش را دقیقاً به این دلیل زنده نگه می‌دارد که تابع درونی یک ارجاع قابل‌دسترسی به آن‌هاست — همین دلیلِ اینکه بستارهای ماندگارِ حاوی اشیای بزرگ، یا شنونده‌های رویدادی که هیچ‌وقت حذف نمی‌شوند، منبع رایج رشد حافظه («نشت») در برنامه‌های طولانی‌مدت‌اند؛ در سطح ۰۹ بیشتر می‌آید.
DOM: یک API مرورگر، نه خود جاوااسکریپتمفهوم

رویداد اعلان مرورگر است که چیزی اتفاق افتاده — یک کلیک، فشردن کلید، ارسال فرم، تمام‌شدن بارگذاری صفحه. شما با اتصال یک تابع شنونده به رویداد واکنش نشان می‌دهید که مرورگر هنگام وقوع آن را صدا می‌زند و یک شیء رویداد که توصیف‌کنندهٔ اتفاق است به آن می‌دهد.

Delegation و preventDefault روی فرم‌هامفهوم

Event delegation عمداً از bubbling استفاده می‌کند: به‌جای اتصال شنونده به هر آیتمِ یک فهرست پویا (که با هر افزودن آیتم باید دوباره وصل می‌شد)، یک شنونده به یک والد پایدار وصل کنید و با event.target تشخیص دهید واقعاً با کدام فرزند تعامل شده.

script.js
list.addEventListener("click", (event) => {
  const item = event.target.closest("li");
  if (!item) return;               // click landed outside any <li>
  item.remove();
});
// Works for EVERY current and future <li>, with a single listener.

فرم‌ها رویداد submit می‌فرستند که عمل پیش‌فرض مرورگر برای آن، بارگذاری مجدد/ناوبری کامل صفحه است — تقریباً همیشه در فرمِ مبتنی بر جاوااسکریپت ناخواسته. با preventDefault() آن را متوقف کنید و خودتان با داده کار کنید:

script.js
form.addEventListener("submit", (event) => {
  event.preventDefault();
  const data = new FormData(form);
  console.log(data.get("email"));   // reads the field named "email"
});
چرا کد ناهمگام (Asynchronous) وجود داردمفهوم

خودِ زبان جاوااسکریپت هر بار یک چیز را روی یک پشتهٔ فراخوانی اجرا می‌کند — مفهوم داخلی‌ای برای اجرای همزمان دو خط از کد شما وجود ندارد. با این حال یک تب مرورگر آشکارا چیزهای زیادی را «همزمان» انجام می‌دهد: دانلود فایل، تیک‌زدن تایمر، انتظار برای شبکه، در حالی که صفحه نسبت به کلیک‌ها پاسخگو می‌ماند. این امکان دارد چون عملیات کند (تایمرها، درخواست‌های شبکه، دسترسی به فایل) توسط خودِ موتور جاوااسکریپت انجام نمی‌شوند — به محیط میزبان (مرورگر یا Node.js) سپرده می‌شوند که انتظار واقعی را بیرون از جاوااسکریپت انجام می‌دهد و بعد، وقتی نتیجه آماده شد، یک کال‌بک، حل‌شدن یک Promise یا یک رویداد به کد شما می‌دهد.

نخستین الگو برای این کار یک کال‌بک ساده بود که به عملیات پاس داده می‌شد:

script.js
console.log("A");
setTimeout(() => console.log("B — runs later"), 1000);
console.log("C");
// Logged order: A, C, B — the script does NOT pause at setTimeout.

تودرتوکردن چند کال‌بکِ ناهمگامِ وابسته، کدی عمیقاً تورفته و سخت‌خوان می‌سازد که غیررسمی «جهنم کال‌بک» (callback hell) نام دارد — دقیقاً مشکلی که Promiseها (درس بعد) و async/await برای حلش معرفی شدند.

حلقهٔ رویداد (Event Loop): پشته، APIهای میزبان و دو صفمفهوم

سازوکار دقیقاً این است: اجرای خودِ جاوااسکریپت تک‌نخی است (یک پشتهٔ فراخوانی)، اما محیط میزبان پشت صحنه نخ‌ها و امکانات اضافه‌ای برای چیزهایی مثل تایمرها و I/O شبکه فراهم می‌کند. وقتی setTimeout را صدا می‌زنید، خودِ تایمر را مرورگر مدیریت می‌کند، نه موتور JS؛ وقتی منقضی شد، کال‌بک بلافاصله اجرا نمی‌شود — در یک صف قرار می‌گیرد. حلقهٔ رویداد سازوکاری است که پیوسته بررسی می‌کند: «پشتهٔ فراخوانی خالی است؟ اگر بله، کال‌بک بعدیِ صف را بردار و روی پشته بگذار تا اجرا شود.»

دو صف وجود دارد و اولویت‌شان یکسان نیست:

  • صف میکروتسک (Microtask) — کال‌بک‌های .then/.catch/.finally در Promise و queueMicrotask. پس از هر بار خالی‌شدن پشته، پیش از اجرای ماکروتسک بعدی، کاملاً تخلیه می‌شود.
  • صف ماکروتسک (Task) — setTimeout، setInterval، رویدادهای DOM، کال‌بک‌های شبکه. در هر دور حلقه یک ماکروتسک اجرا می‌شود.

Promiseها: pending، fulfilled، rejectedمفهوم

Promise شیئی است که یک مقدار را نمایندگی می‌کند که هنوز در دسترس نیست، اما بالاخره خواهد بود — یا حل‌شده (fulfilled با یک مقدار) یا ردشده (rejected با یک دلیل). در هر لحظه دقیقاً در یکی از سه وضعیت است و وقتی از pending خارج شد دیگر هرگز وضعیتش عوض نمی‌شود.

مدل ذهنی
pending←fulfilled (مقدار دارد)
pending←rejected (دلیل دارد)
script.js
function wait(ms) {
  return new Promise((resolve, reject) => {
    if (ms < 0) return reject(new Error("negative delay"));
    setTimeout(() => resolve(`waited ${ms}ms`), ms);
  });
}

wait(500)
  .then(result => {
    console.log(result);      // "waited 500ms"
    return wait(200);          // returning a Promise CHAINS it
  })
  .then(result => console.log(result)) // "waited 200ms"
  .catch(err => console.error("Failed:", err.message))
  .finally(() => console.log("Done, either way"));

زنجیره‌سازی کار می‌کند چون خودِ .then() یک Promise جدید برمی‌گرداند — اگر کال‌بک Promise دیگری برگرداند، زنجیره منتظرش می‌ماند؛ اگر مقداری ساده برگرداند، .then() بعدی مستقیم همان را دریافت می‌کند. یک .catch() در انتهای زنجیره ردشدن هر گام قبلی را می‌گیرد.

async/await و ترکیب‌کننده‌های Promiseمفهوم

async/await شکرِ سینتکسی روی Promiseهاست — جایگزینشان نمی‌شود و کد را همزمان نمی‌کند. تابع async همیشه یک Promise برمی‌گرداند؛ await آن تابع (نه کل برنامه) را متوقف می‌کند تا Promise موردانتظار تعیین تکلیف شود.

script.js
async function loadProfile() {
  try {
    const user = await wait(300).then(() => ({ name: "Aya" }));
    const posts = await wait(300).then(() => ["post1", "post2"]);
    return { user, posts };
  } catch (err) {
    console.error("loadProfile failed:", err.message);
    throw err;                     // re-throw if the caller should also know
  }
}

loadProfile().then(profile => console.log(profile));

از try/catch دور await دقیقاً مثل مدیریت خطای همزمان استفاده کنید (سطح ۰۸ try/catch را کامل پوشش می‌دهد) — ردشدنِ یک Promiseِ await‌شده در همان خطِ await پرتاب می‌شود. وقتی چند عملیات ناهمگامِ مستقل به هم وابسته نیستند، یکی‌یکی await‌کردن‌شان زمان هدر می‌دهد؛ ترکیب‌کننده‌های زیر آن‌ها را همزمان اجرا می‌کنند:

script.js
// Promise.all — waits for ALL; rejects immediately if ANY one rejects
const [a, b] = await Promise.all([wait(100), wait(200)]);

// Promise.allSettled — waits for ALL, never short-circuits;
// gives you each result's status individually
const results = await Promise.allSettled([wait(100), Promise.reject("x")]);
// [{status:"fulfilled", value:...}, {status:"rejected", reason:"x"}]

// Promise.race — settles as soon as the FIRST one settles (win or lose)
const first = await Promise.race([wait(100), wait(500)]);

// Promise.any — settles as soon as the FIRST one FULFILLS,
// ignoring rejections unless ALL of them reject
const firstSuccess = await Promise.any([Promise.reject("no"), wait(50)]);
اشتباه رایجتابع asyncای که Promise آن هرگز .catch() نشود، یا داخل try/catch await نشود، یک ردشدنِ مدیریت‌نشدهٔ Promise تولید می‌کند — به‌صورت هشدار مرورگر لاگ می‌شود و وضعیت برنامه را بی‌صدا می‌بلعد که ردگیری‌اش تا منبع می‌تواند بسیار سخت باشد.
Fetch و HTTPمفهوم

fetch یک API میزبان (مرورگر و Node.js) برای ساخت درخواست‌های HTTP است و یک Promise برمی‌گرداند. کجا اجرا کنیم: فراخوانی واقعی شبکه به یک سرور واقعی نیاز دارد — قطعه‌کدهای زیر را در script.js پروژهٔ خودتان یا کنسول مرورگر روی یک endpoint واقعی امتحان کنید، نه داخل همین صفحهٔ دوره.

script.js — fetch واقعی، در پروژهٔ خودتان اجرا کنید
async function getUser(id) {
  const response = await fetch(`https://api.example.com/users/${id}`);

  if (!response.ok) {
    // fetch does NOT reject on 404/500 — you must check .ok yourself!
    throw new Error(`Request failed: ${response.status}`);
  }

  return response.json();  // ALSO returns a Promise — parses the JSON body
}

async function createUser(name) {
  const response = await fetch("https://api.example.com/users", {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify({ name }),
  });
  if (!response.ok) throw new Error(`Failed: ${response.status}`);
  return response.json();
}
اشتباه رایج، که ارزش تکرار داردPromiseِ fetch فقط در شکست واقعی شبکه (آفلاین بودن، خطای DNS، مسدودشدن توسط CORS) رد می‌شود — پاسخ 404 یا 500 از نظر Promise همچنان یک fetch «موفق» است. همیشه خودتان response.ok (برای وضعیت‌های ۲۰۰ تا ۲۹۹ برابر true) یا response.status را بررسی کنید.

متدهای HTTP قصد را مشخص می‌کنند: GET (خواندن، بدون body)، POST (ایجاد)، PUT (جایگزینی کامل)، PATCH (به‌روزرسانی جزئی)، DELETE (حذف). کدهای وضعیت بر اساس رقم اول گروه‌بندی می‌شوند: 2xx موفقیت، 3xx تغییر مسیر، 4xx مشکلی در درخواست (401 احراز نشده، 403 ممنوع، 404 پیدا نشد)، 5xx شکست سمت سرور.

دموی شبیه‌سازی‌شده — همان شکل Promise/async یک fetch واقعیشبکهٔ ساختگی، آفلاین اجرا می‌شود

این صفحه نمی‌تواند فراخوانی‌های شبکهٔ cross-origin واقعی بزند، پس دکمه‌های زیر یک تابع ساختگیِ کوچک را صدا می‌زنند که با تأخیر یک Promise برمی‌گرداند — از نظر ساختار با چیزی که fetch می‌دهد یکسان است. هر دو دکمه را امتحان کنید تا بررسی .ok/status را در عمل ببینید.

fetchی که دیگر لازم نیست (کاربر از صفحه رفته، عبارت جست‌وجوی جدیدی تایپ کرده) باید لغو شود، نه اینکه تمام شود و دور ریخته شود — AbortController این را ممکن می‌کند:

script.js
const controller = new AbortController();

fetch("/search?q=term", { signal: controller.signal })
  .then(res => res.json())
  .catch(err => {
    if (err.name === "AbortError") console.log("Request was cancelled");
    else console.error(err);
  });

// later, e.g. when the user types again before the first request finished:
controller.abort();
سیاست هم‌مبدأ (Same-Origin Policy) و CORSمفهوم

مبدأ (origin) ترکیبی از scheme + host + port است (https://example.com:443). سیاست هم‌مبدأ مرورگر به‌طور پیش‌فرض مانع می‌شود جاوااسکریپتِ یک صفحه پاسخ‌های مبدأ دیگر را بخواند — مرزی امنیتی که ربطی به این ندارد که خودِ درخواست روی شبکه «مجاز» است یا نه؛ ممکن است درخواست به سرور برسد، اما مرورگر از تحویل پاسخ به اسکریپت شما امتناع می‌کند.

CORS (Cross-Origin Resource Sharing) سازوکاری است که آن محدودیت را شُل می‌کند: سروری که می‌خواهد دسترسی جاوااسکریپتِ cross-origin را مجاز کند با هدرهایی مثل Access-Control-Allow-Origin پاسخ می‌دهد و مرورگر پیش از تحویل پاسخ به کد شما آن‌ها را بررسی می‌کند. برای درخواست‌های غیرساده (هدرهای سفارشی، متدهایی غیر از GET/POST با body ساده)، مرورگر ابتدا خودکار یک درخواست preflight از نوع OPTIONS می‌فرستد تا اجازه بخواهد.

CORS سازوکار مرورگر است، نه فایروال سرورنبودِ هدر CORS مانع پردازش درخواست توسط سرور نمی‌شود (آن قبلاً انجام شده) — مانع می‌شود مرورگر اجازه دهد جاوااسکریپت شما پاسخ را بخواند. ابزارهایی مثل curl، یا درخواست از یک سرور بک‌اند به بک‌اند دیگر کاملاً تحت‌تأثیر نیستند چون CORS فقط توسط مرورگرها و برای جاوااسکریپتِ اجراشده در مرورگر اعمال می‌شود.

Node.js و npm، به‌صورت مفهومیمفهوم

Node.js یک محیط اجرای جاوااسکریپت ساخته‌شده روی موتور V8 کروم است که برای اجرا بیرون از مرورگر طراحی شده — برای سرورها، ابزارهای ساخت و اسکریپت‌های خط فرمان. APIهای میزبانی اضافه می‌کند که مرورگر ندارد (fs برای فایل‌سیستم، process برای محیط برنامهٔ در حال اجرا) و هیچ‌کدام از APIهای مرورگر را ندارد (بدون document، بدون DOM).

Node.js از قدیم سیستم ماژول خودش را داشت، یعنی CommonJS (require()/module.exports) که قدیمی‌تر از ماژول‌های ES است. Node.js مدرن هر دو را پشتیبانی می‌کند — CommonJS به‌طور پیش‌فرض در فایل‌های .js، و ماژول‌های ES وقتی فایل به .mjs ختم شود یا نزدیک‌ترین package.json مقدار "type": "module" داشته باشد.

CommonJS (پیش‌فرض قدیمی Node.js)
// exporting
module.exports = { add, PI };
// importing
const { add, PI } = require("./math.js");

npm (Node Package Manager) کد شخص ثالث را نصب و مدیریت می‌کند. package.json یک پروژه، dependencies (برای اجرا لازم) و devDependencies (فقط هنگام توسعه لازم، مثل اجراکنندهٔ تست) را فهرست می‌کند، به‌علاوهٔ scripts سفارشی که با npm run <name> اجرا می‌شوند. یک lockfile (package-lock.json) نسخه‌های دقیق نصب‌شده را ثابت می‌کند تا پروژه روی هر ماشین یکسان رفتار کند. نسخهٔ بسته‌ها معمولاً از نسخه‌گذاری معنایی (MAJOR.MINOR.PATCH) پیروی می‌کند — افزایش major یعنی تغییرهای ناسازگار.

مدیریت خطا: throw، try/catch/finally و خطاهای سفارشیمفهوم
script.js
function withdraw(balance, amount) {
  if (amount > balance) {
    throw new Error("Insufficient funds");
  }
  return balance - amount;
}

try {
  const newBalance = withdraw(100, 150);
} catch (error) {
  console.error("Withdrawal failed:", error.message);
} finally {
  console.log("Attempt finished — this always runs");
}

// Custom error class — carries structured extra information
class InsufficientFundsError extends Error {
  constructor(shortfall) {
    super(`Insufficient funds: short by ${shortfall}`);
    this.name = "InsufficientFundsError";
    this.shortfall = shortfall;
  }
}

try {
  throw new InsufficientFundsError(50);
} catch (err) {
  if (err instanceof InsufficientFundsError) {
    console.log("Shortfall was:", err.shortfall);
  }
}

خطایی که هیچ‌جا گرفته نشود در پشتهٔ فراخوانی منتشر می‌شود، تابع به تابع، تا اینکه یا یک try/catch آن را مدیریت کند یا به بالا برسد و اسکریپت را از کار بیندازد (یا برای Promise، تبدیل به ردشدن مدیریت‌نشده شود — سطح ۰۷). خطاها را در سطحی بگیرید که واقعاً بتوانید کار معناداری دربارهٔ آن‌ها بکنید؛ گرفتنِ زودهنگام (و بلعیدن بی‌صدای خطا) باگ‌های واقعی را پنهان می‌کند.

چرا و چگونه جاوااسکریپت تست می‌شودمفهوم

تست، کدی است که درست‌بودنِ کد دیگر را خودکار و تکرارپذیر، بدون اینکه انسانی بعد از هر تغییر برنامه را کلیک‌کلیک کند، بررسی می‌کند. تست واحد (unit test) یک تابع یا ماژول را در انزوا بررسی می‌کند؛ تست یکپارچگی (integration test) بررسی می‌کند چند واحد با هم درست کار می‌کنند (مثلاً ارسال فرم واقعاً DOM را به‌روز کند). هر دو به assertionها تکیه دارند — گزاره‌هایی که اگر مقداری آنچه انتظار می‌رود نباشد بلند شکست می‌خورند.

math.test.js — شکل مفهومی، مستقل از فریم‌ورک
function add(a, b) { return a + b; }

// Every modern JS test framework (Vitest, Jest, Node's built-in
// "node:test") shares roughly this same shape:
test("add() sums two positive numbers", () => {
  expect(add(2, 3)).toBe(5);
});

test("add() handles negative numbers", () => {
  expect(add(-1, -1)).toBe(-2);
});

test("add() handles the edge case of zero", () => {
  expect(add(0, 0)).toBe(0);
});

تست‌های خوب عمداً حالت‌های لبه (آرایهٔ خالی، صفر، عددهای منفی، بزرگ‌ترین ورودی مجاز) را شامل می‌شوند، نه فقط «مسیر خوش». Mocking یک وابستگی واقعی (فراخوانی شبکه، تاریخ فعلی، پایگاه‌داده) را با یک جانشین ساختگی و قابل‌کنترل عوض می‌کند، تا تست به دردسترس‌بودن یا قابل‌پیش‌بینی‌بودن سیستم‌های بیرونی وابسته نباشد. تستِ کد ناهمگام تابع موردآزمون را مثل کد برنامه await می‌کند، سپس مقدار حل‌شده یا ردشدهٔ گرفته‌شده را بررسی می‌کند. توابع خالص (سطح ۰۵) به‌مراتب راحت‌تر از توابع با اثر جانبی تست می‌شوند، چون خروجی‌شان فقط به ورودی بستگی دارد.

اسکریپت‌نویسی بین‌سایتی (XSS)امنیت

XSS وقتی رخ می‌دهد که مهاجم بتواند جاوااسکریپت خودش را داخل صفحهٔ شما، در بافت نشست یک کاربر قانونی اجرا کند — یعنی بتواند کوکی بخواند، به نام آن کاربر درخواست بزند یا صفحه‌ای را که او می‌بیند دست‌کاری کند. DOM-based XSS به‌طور خاص از جاوااسکریپتِ سمت کلاینت سرچشمه می‌گیرد که داده‌ٔ نامطمئن را به شکلی در صفحه می‌نویسد که مرورگر اجرایش کند.

الگوی آسیب‌پذیر ← الگوی امن
script.js
// VULNERABLE — a URL parameter rendered straight into HTML
const name = new URLSearchParams(location.search).get("name");
greeting.innerHTML = `Hello, ${name}!`;
// If name is <img src=x onerror=stealCookies()>, it EXECUTES.

// SAFE — treated as text, never parsed as markup
greeting.textContent = `Hello, ${name}!`;

// SAFE, if you genuinely need to insert an element:
const strong = document.createElement("strong");
strong.textContent = name;   // still text — never markup
greeting.append("Hello, ", strong, "!");

راهکار، در سطح مفهومیِ این دوره: برای هر چیزی که از ورودی کاربر، پارامترهای URL یا پاسخ APIها می‌آید به‌جای innerHTML پیش‌فرضتان textContent باشد؛ عناصر را به‌جای الحاق رشتهٔ HTML با createElement بسازید؛ و هر مقداری را که مستقیم از کد منبع خودتان نیامده تا خلافش ثابت نشده نامطمئن فرض کنید.

در localStorage/sessionStorage ذخیره نکنیدتوکن‌های احراز هویت که باید برای جاوااسکریپت غیرقابل‌دسترس باشند، شناسه‌های نشست، رمزهای عبور، یا هر دادهٔ دیگری که یک باگ XSS نباید به‌سادگی بتواند استخراجش کند. توکن‌های حساس نشست معمولاً بهتر است در یک کوکی HttpOnly (کاملاً نامرئی برای جاوااسکریپت) نگه داشته شوند که سرور آن را با ویژگی‌های مناسب Secure و SameSite تنظیم می‌کند.
CSRF، سیاست امنیت محتوا (CSP) و prototype pollutionامنیت

CSRF (Cross-Site Request Forgery) مرورگر کاربرِ واردشده را فریب می‌دهد تا از یک سایت دیگرِ مخرب، به سایتی که در آن احراز شده درخواستی بفرستد — با سوءاستفاده از اینکه کوکی‌ها خودکار ضمیمه می‌شوند. دفاع‌های مدرن شامل ویژگی کوکیِ SameSite و توکن‌های ضد-CSRF صادرشده از سرور است؛ این مسئله عمدتاً سمت سرور حل می‌شود، اما توسعه‌دهندگان فرانت‌اند باید هنگام طراحی GETهای تغییردهندهٔ وضعیت (از آن‌ها پرهیز کنید — GET هرگز نباید داده را تغییر دهد) یا فرم‌ها این ریسک را بشناسند.

سیاست امنیت محتوا (Content Security Policy یا CSP) هدر پاسخی است که به مرورگر می‌گوید چه منابعی برای اسکریپت، استایل و سایر منابع مجازند در صفحه بارگذاری و اجرا شوند — لایهٔ دفاع در عمق که حتی اگر در جای دیگر باگ XSS باشد، می‌تواند از اجرای یک تگ <script> تزریق‌شده جلوگیری کند. این دقیقاً همان سازوکاری است که محیط میزبانیِ خودِ این دوره روی صفحه‌های تولیدشده اعمال می‌کند.

Prototype pollution آسیب‌پذیری‌ای است که در آن ورودیِ کنترل‌شده توسط مهاجم به کلیدی مثل "__proto__" در یک تابع ادغام یا کلون عمیق شیء می‌رسد و به مهاجم اجازه می‌دهد ویژگی‌هایی روی خودِ Object.prototype تزریق کند — که بی‌صدا روی هر شیء در برنامه اثر می‌گذارد. بیشتر وقت‌ها توسط ابزارهای ساده‌انگارانهٔ ادغام بازگشتی ایجاد می‌شود که از نام‌های کلیدیِ ویژه محافظت نمی‌کنند.

ریسک زنجیرهٔ تأمین: وابستگی‌های npmامنیت

یک پروژهٔ معمولی به ده‌ها بسته وابسته است و هرکدام ممکن است به ده‌ها بستهٔ دیگر وابسته باشند. هرکدام کدی است که شما ننوشته‌اید و با همان امتیازات کد خودتان اجرا می‌شود — وابستگیِ دچار نفوذ یا به‌روزرسانی‌شدهٔ مخرب (یا یکی از وابستگی‌های خودش) می‌تواند برنامهٔ شما را تحت‌تأثیر قرار دهد. عادت‌های عملی: وابستگی‌ها را عمدی و نه کورکورانه به‌روز کنید، پیش از افزودن وابستگی جدید برای یک کار پیش‌پاافتاده بررسی کنید واقعاً چه می‌کند، از lockfile استفاده کنید تا نصب‌ها تکرارپذیر باشند، و به خروجی ممیزیِ آسیب‌پذیریِ داخلیِ مدیر بسته‌تان توجه کنید.

کارایی: کار غیرضروری، debounce و throttleمفهوم

رایج‌ترین مشکل کارایی در فرانت‌اند الگوریتمِ ناکارآمد نیست — انجام کار گران‌قیمت خیلی بیشتر از لازم است. پرس‌وجو/تغییر مکررِ DOM داخل حلقه، یا اجرای یک جست‌وجوی کامل با هر ضربهٔ کلید، مقصران کلاسیک‌اند. دو تکنیک مرتبط حالت ضربهٔ کلید را حل می‌کنند:

  • Debounce — صبر کن تا کاربر برای یک تأخیر مشخص از فعال‌کردن رویداد دست بکشد، بعد یک بار اجرا کن. برای جست‌وجو-هنگام-تایپ ایده‌آل است.
  • Throttle — حداکثر یک بار در هر بازهٔ زمانیِ ثابت اجرا کن، مهم نیست رویداد چقدر زیاد فعال شود. برای هندلرهای scroll/resize ایده‌آل است.
script.js
function debounce(fn, delay) {
  let timeoutId;
  return function (...args) {
    clearTimeout(timeoutId);
    timeoutId = setTimeout(() => fn.apply(this, args), delay);
  };
}

const debouncedSearch = debounce((query) => runSearch(query), 300);
input.addEventListener("input", (e) => debouncedSearch(e.target.value));

فراتر از debounce/throttle: نوشتن‌های DOM را دسته‌ای انجام دهید به‌جای اینکه با خواندن‌ها درهم‌تنیده شوند (درهم‌تنیدگی مرورگر را مجبور می‌کند چینش (layout) را مکرر دوباره محاسبه کند — هزینه‌ای به نام «layout thrashing»)، از نگه‌داشتن ارجاع‌هایی که زباله‌روب را بیش از لازم عقب می‌اندازند پرهیز کنید (سطح ۰۶)، و پیش از بهینه‌سازی به‌جای حدس‌زدن با پنل Performance در DevTools پروفایل بگیرید.

کیفیت کد و بازآرایی (Refactoring)مفهوم

«کدی که اجرا می‌شود» و «کدی که قابل نگه‌داری است» دو سطح متفاوت‌اند. دومی نام‌گذاری روشن، توابع کوچک با یک مسئولیت، حداقل اثر جانبی و ساختاری می‌خواهد که تغییر بعدی (توسط شما، شش ماه بعد، بعد از فراموش‌کردن همهٔ این‌ها) را آسان کند، نه پرریسک.

نسخهٔ ۲ — شفاف و ماژولار
function sumPaidInvoices(invoices) {
  return invoices
    .filter(invoice => invoice.status === "paid")
    .reduce((total, invoice) => total + invoice.amount, 0);

نسخهٔ ۲ «پیشرفته‌تر» نیست — هر تکنیکی که به کار برده همان است که از سطح ۰۴ می‌شناسید. بهتر است چون خواننده‌ای که هرگز شکل داده را ندیده می‌تواند فقط از روی نام‌ها بفهمد چه می‌کند، نمی‌تواند به‌طور تصادفی ورودی‌اش را تغییر دهد، و تمیز با دیگر کدهای پردازش آرایه ترکیب می‌شود. جهتِ بازآرایی همین است: خوانا ← ماژولار ← (سطح ۰۸) تست‌پذیر، بدون تغییر رفتار.

ساختاردهی یک برنامهٔ واقعیمفهوم

یک اسکریپت کوچک می‌تواند همه‌چیز را در یک فایل بگذارد. برنامه‌ای که قرار است رشد کند به تفکیک دغدغه‌ها (separation of concerns) نیاز دارد: کدی که داده را می‌گیرد، کدی که آن را تبدیل می‌کند و کدی که در DOM رندرش می‌کند باید در ماژول‌های جدا و مستقل‌قابل‌تست (سطح ۰۸) باشند، نه یک تابع درهم‌پیچیده.

یک چینش فایل نمونه برای برنامهٔ کوچک
/src
  /api        → fetch calls only, returns plain data (Level 07)
  /state      → the single source of truth for application data
  /components → functions that build/update DOM from state (Level 06)
  /utils      → pure helper functions (Level 05), easy to unit test
  main.js     → wires the above together, handles top-level events

یک الگوی ساده و بدون فریم‌ورک برای state: داده‌ٔ برنامه را در یک شیء ساده نگه دارید، توابعی برای تغییرش در دسترس بگذارید و هر بار که تغییر کرد دوباره رندر کنید — همان ایده‌ای که هر فریم‌ورک بزرگ UI روی آن بنا شده، فقط بدون ابزارهایش.

state.js
let state = { items: [], filter: "all" };
const listeners = [];

export function getState() { return state; }
export function setState(patch) {
  state = { ...state, ...patch };   // immutable update (Level 04)
  listeners.forEach(fn => fn(state));
}
export function subscribe(fn) { listeners.push(fn); }

تمرین خواندن کد

این ماژول ناآشنا را بخوانید و به پنج سؤال پاسخ دهیدتمرین
let cache = new Map();

export async function getUser(id) {
  if (cache.has(id)) return cache.get(id);
  const res = await fetch(`/api/users/${id}`);
  if (!res.ok) throw new Error(`User ${id} not found`);
  const user = await res.json();
  cache.set(id, user);
  return user;
}

export function clearCache() {
  cache = new Map();
}

بدون اجرا: (۱) ورودی و خروجی getUser چیست؟ (۲) وضعیت سطح ماژول چیست؟ (۳) چه چیزی ناهمگام است و چه چیزی می‌تواند خطا پرتاب کند؟ (۴) اگر getUser(5) دو بار پشت‌سرهم صدا زده شود چه می‌شود؟ (۵) اگر id بتواند همان کاربر را با دو نوع متفاوت نشان دهد، مثلاً 5 در برابر "5"، این ماژول چه باگ واقع‌بینانه‌ای را می‌تواند پنهان کند؟

نمایش پاسخ

(۱) ورودی: شناسهٔ کاربر؛ خروجی: Promiseای که به شیء کاربر حل می‌شود، یا Promiseِ ردشده/خطای پرتاب‌شده. (۲) Mapِ cache که بین هر فراخوانی به این ماژول مشترک است. (۳) فراخوانی‌های fetch و .json() ناهمگام‌اند؛ پاسخ غیر OK یا شکست شبکه می‌تواند پرتاب/reject کند. (۴) فراخوانی دوم بدون درخواست شبکهٔ جدید فوراً از cache برمی‌گرداند. (۵) کلیدهای Map با برابری سخت‌گیرانه و بدون تبدیل نوع مقایسه می‌شوند — 5 و "5" کلیدهای متفاوت‌اند، پس همان کاربر می‌تواند دو بار با دو «هویت» متفاوت fetch و cache شود، که بی‌صدا فراخوانی‌های شبکه را دو برابر می‌کند و خطر دادهٔ تکراریِ کهنه را به همراه دارد.

کار واقعی کجا اتفاق می‌افتدکار سطح ۱۰ همین گردش‌کار و طرز فکر بالاست — سیستم پروژه‌ها در ادامه جایی است که واقعاً آن را به کار می‌بندید و از یک شمارندهٔ مقدماتی تا پروژهٔ نهایی چنددامنه‌ای پیش می‌روید. هر پروژهٔ آن‌جا را درس‌نامهٔ واقعیِ این سطح بدانید.

storage.js — نقطهٔ شروع
const KEY = "todos";

export function loadTodos() {
  try {
    const raw = localStorage.getItem(KEY);
    return raw ? JSON.parse(raw) : [];
  } catch {
    console.warn("Corrupted todo data, resetting.");
    return [];
  }
}

export function saveTodos(todos) {
  localStorage.setItem(KEY, JSON.stringify(todos));
}

۱۱. مدیر کارهای ناهمگامپیشرفته
هدف

تمرین حالت‌های واقعی UI ناهمگام — بارگذاری، موفقیت و خطا — در برابر یک شبکهٔ ساختگیِ ناپایدار.

نیازمندی‌ها
  • افزودن، تکمیل و حذف یک کار هرکدام از طریق یک async function شبیه‌سازِ ذخیره می‌گذرد (تأخیر تصادفی، رد ساختگیِ گاهی)

  • عمل تلاش مجدد روی ذخیره‌های ناموفق
  • برای عمل «همگام‌سازی همه» از Promise.allSettled استفاده کنید که همهٔ کارهای فعلاً ناموفق را یک‌جا دوباره امتحان کند
معماری

به api.js (توابع شبکهٔ ساختگی که Promise برمی‌گردانند)، state.js (فهرست کارها و پرچم‌های وضعیت) و ui.js (رندر) تقسیم کنید — کاربرد مستقیم چینش فایل سطح ۱۰.

۱۲. داشبورد داده‌ٔ زنده (Fetch + JSON)پیشرفته
هدف

نخستین پروژهٔ شما در برابر یک API واقعی HTTP — آن را در پوشهٔ پروژهٔ خودتان و روی یک API عمومیِ واقعی به انتخاب خودتان بسازید و اجرا کنید، چون خود صفحهٔ این دوره نمی‌تواند فراخوانی شبکهٔ خروجی بزند.

نیازمندی‌ها
  • هنگام بارگذاری یک فهرست را از یک endpoint واقعی بگیرید و تا حل‌شدن، نشانگر بارگذاری نشان دهید
  • response.ok را بررسی کنید و روی شکست یک حالت خطای مجزا و خوانا رندر کنید (سطح ۰۷)
  • یک فیلد جست‌وجو که پیش از شروع درخواست جدید، درخواست در حال انجام قبلی را با AbortController لغو کند
  • نتایج را فقط با textContent/createElement رندر کنید — داده‌ٔ API نامطمئن است (سطح ۰۹)
api.js — نقطهٔ شروع (URL را برای API انتخابی‌تان ویرایش کنید)
let controller;

export async function search(query) {
  controller?.abort();          // cancel any request still in flight
  controller = new AbortController();

  const res = await fetch(`https://example-api.test/search?q=${encodeURIComponent(query)}`,
    { signal: controller.signal });

  if (!res.ok) throw new Error(`Search failed: ${res.status}`);
  return res.json();
}

// api/syncApi.js
export function pushTasks(tasks) {
  return new Promise((resolve, reject) => {
    const delay = 400 + Math.random() * 800;
    setTimeout(() => {
      if (Math.random() < 0.15) {
        reject(new Error("Sync failed: server unreachable"));
      } else {
        resolve({ syncedAt: Date.now(), count: tasks.length });
      }
    }, delay);
  });
}

این دقیقاً شکل یک لایهٔ API مبتنی بر fetch (سطح ۰۷) را بازتاب می‌دهد — عوض‌کردن داخلیاتِ این تابع با یک فراخوانی واقعی fetch، بدون تغییر در هیچ فراخواننده‌ای، گسترش طبیعیِ نخست پس از داشتن بک‌اند واقعی است.

مدیریت خطا
  • persistence.js هرگز نمی‌گذارد مقدار ذخیره‌شدهٔ خراب راه‌اندازی را کرش کند — می‌گیرد، هشدار لاگ می‌کند و به state خالی برمی‌گردد (سناریوی اشکال‌زدایی سطح ۰۸، حل‌شده در سطح معماری)
  • ردشدن‌های syncApi در محل فراخوانی در main.js گرفته می‌شود و state.sync را به‌روز می‌کند، نه اینکه مدیریت‌نشده پرتاب شود
  • Import پیش از پذیرش شکلِ تجزیه‌شده را اعتبارسنجی می‌کند (آرایه بودن، داشتن فیلدهای مورد انتظار در هر آیتم) و در غیر این صورت یک ValidationError توصیفی پرتاب می‌کند
برنامهٔ تست
  • تست واحد برای هر تابع در utils/validate.js، از جمله حالت‌های لبه: عنوان خالی، فهرست برچسب با تکراری، یادداشتی بسیار بلند
  • تست واحد برای persistence.js در برابر یک رشتهٔ ذخیره‌شدهٔ عمداً خراب
  • یک اسکریپت تست دستی که هر جریان کاربر بالا را پوشش دهد و پس از هر تغییر مهم اجرا شود
