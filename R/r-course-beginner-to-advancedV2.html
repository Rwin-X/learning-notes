BEGINNER

01R چیست و چرا متفاوت استmental model

زبان R در اصل برای تحلیل آماری طراحی شده، نه برای برنامه‌نویسی عمومی. همین ریشه باعث شده چند مفهوم پایه با زبان‌های دیگری که شاید پیش‌تر دیده باشید، تفاوت داشته باشد.

همه‌چیز وکتور استvectorized

حتی یک عدد تکی در R یک وکتور به طول یک است. عملیات روی وکتورها به‌صورت عنصر‌به‌عنصر انجام می‌شود، بدون نیاز به حلقه‌ی دستی.

شمارش از یک آغاز می‌شود1-indexed

برخلاف بسیاری از زبان‌های برنامه‌نویسی، نخستین عضو یک وکتور با x[1] به‌دست می‌آید، نه x[0].

عملگر انتساب assignment

علامت رایج برای انتساب مقدار، پیکان چپ (<-) است. علامت مساوی نیز کار می‌کند، اما در میان برنامه‌نویسان R رایج‌تر نیست.

مقدار گم‌شده بخشی از زبان استNA

مقدار NA نشان‌دهنده‌ی داده‌ی گم‌شده است و یک شهروند درجه‌یک در زبان به‌شمار می‌رود، نه یک استثنا.

اگر از پایتون می‌آیید وکتور در R از نظر رفتار به numpy.array نزدیک‌تر است تا لیست پایتون. data.frame معادل pandas.DataFrame است، و بسته‌ی tidyverse همان روحیه‌ی pandas و matplotlib را دارد، با این تفاوت که از عملگر pipe به‌جای زنجیره‌ی متدها استفاده می‌کند.
تمرین ۱

بدون اجرا کردن کد، پیش‌بینی کنید نتیجه‌ی c(1,2,3)[0] در R چیست و چرا با پایتون فرق دارد.

نمایش پاسخ 
c(1,2,3)[0]
# result: numeric(0) -- an empty vector, not an error and not the first element

شمارش در R از ۱ آغاز می‌شود، پس ایندکس صفر به هیچ عضوی اشاره نمی‌کند. R به‌جای صدور خطا، یک وکتور خالی از همان نوع برمی‌گرداند؛ این رفتار با پایتون که IndexError یا عضو اول را برمی‌گرداند، کاملاً متفاوت است.

04وکتور، ستون فقرات زبان Rvectors

تقریباً تمام عملیات عددی در زبان R حول محور وکتور می‌چرخد. درک درست این بخش، پایه‌ی فهم درست بقیه‌ی زبان است.

vectors.R
# creating a vector with c() -- combine
v <- c(10, 20, 30, 40)

# numeric sequences
1:10              # 1 2 3 ... 10
seq(0, 1, by=0.25)
seq(1, 10, length.out=5)

# repetition
rep(c(1,2), times=3)   # 1 2 1 2 1 2
rep(c(1,2), each=3)    # 1 1 1 2 2 2

# operating on the whole vector, no loop needed
v * 2          # 20 40 60 80
v + c(1,1,1,1) # element-wise sum
v > 25         # TRUE/FALSE for each element

# statistics over a vector
sum(v); mean(v); max(v); min(v); length(v); sd(v)
بازچرخانی وکتور (recycling) اگر دو وکتور با طول متفاوت را با هم جمع کنید، R وکتور کوتاه‌تر را به‌صورت خودکار تکرار می‌کند تا طول هر دو برابر شود، بدون آن‌که خطایی صادر شود (گاهی فقط یک هشدار نمایش داده می‌شود). این رفتار می‌تواند منشأ خطاهای پنهان باشد، پس همیشه طول وکتورها را بررسی کنید.
recycling-example.R
c(1,2,3,4) + c(10,20)
# result: 11 22 13 24 -- the second vector repeated twice
تمرین ۴ — پایان سطح پایه

وکتوری از اعداد ۱ تا ۲۰ بسازید. بدون استفاده از حلقه، فقط اعدادی را استخراج کنید که بر ۳ بخش‌پذیرند و مجموع آن‌ها را حساب کنید.

نمایش پاسخ 
nums <- 1:20
divisible_by_3 <- nums[nums %% 3 == 0]
divisible_by_3     # 3 6 9 12 15 18
sum(divisible_by_3) # 63

عملگر %% باقی‌مانده‌ی تقسیم را می‌دهد و nums %% 3 == 0 یک وکتور منطقی تولید می‌کند که برای فیلتر کردن استفاده شده است؛ دقیقاً همان مفهوم بردارش که در این بخش دیدید، بدون نیاز به حلقه.

05ایندکس‌گذاری و زیرمجموعه‌گیریindexing & subsetting

سه روش اصلی برای دسترسی به عناصر وجود دارد: بر اساس موقعیت عددی، بر اساس نام، و بر اساس شرط منطقی. روش سوم پرکاربردترین روش در تحلیل داده است.

indexing.R
v <- c(a=5, b=10, c=15, d=20)

v[1]          # first element (indexing starts at 1)
v[c(1,3)]     # first and third elements
v[-1]         # everything except the first -- negative means drop
v["b"]        # access by name
v[v > 10]     # logical filter -- only elements passing the condition

# replacement uses the same syntax
v[v > 10] <- 0   # zero out every element greater than 10
عملگرنحوکاربرد
براکت تکیx[i]زیرمجموعه می‌گیرد، نوع ساختار اصلی حفظ می‌شود
براکت دوتاییx[[i]]یک عضو را از فهرست استخراج می‌کند، بدون بسته‌بندی
علامت دلارx$nameدسترسی به ستون یا فیلد با نام، در فهرست و قاب داده
تفاوت [ ] و [[ ]] در فهرست دستور list[1] یک زیرفهرست با یک عضو برمی‌گرداند که خود همچنان از نوع فهرست است. دستور list[[1]] محتوای همان عضو را بدون بسته‌بندی برمی‌گرداند. این تفاوت شبیه تفاوت میان برش (slice) و دسترسی تکی در پایتون است، با این تفاوت که در R نوع خروجی را نیز تغییر می‌دهد.
تمرین ۵

وکتور نام‌دار v <- c(math=18, physics=15, chemistry=19) را بسازید. با ایندکس‌گذاری منطقی، فقط نمراتی را نگه دارید که از ۱۶ بالاترند.

نمایش پاسخ 
v <- c(math=18, physics=15, chemistry=19)
v[v > 16]
# math chemistry
#   18       19

نام هر عضو هنگام فیلتر کردن حفظ می‌شود، چون براکت تکی ساختار اصلی وکتور (شامل نام‌ها) را نگه می‌دارد؛ این همان نکته‌ای است که در جدول بالا با عنوان «نوع ساختار اصلی حفظ می‌شود» به آن اشاره شد.

فهرست list()

ماتریس matrix()

m <- matrix(1:6, nrow=2, ncol=3)
m[1, ]     # entire first row
m[, 2]     # entire second column

m %*% t(m) # matrix multiplication

برخلاف قاب داده، همه‌ی عناصر یک ماتریس باید از یک نوع باشند.

متغیر دسته‌ای factor

grade <- factor(c("low", "high", "mid"),
                levels = c("low", "mid", "high"),
                ordered = TRUE)
grade < "high"   # TRUE FALSE TRUE -- it understands the order

برای ستون‌های دسته‌ای، مانند جنسیت، سطح تحصیلات یا رتبه‌بندی، بهتر است از factor استفاده شود، نه از رشته‌ی خام. مدل‌های آماری و بسته‌ی ggplot رفتار متفاوتی نسبت به داده‌ی دسته‌ای دارند. این مفهوم پایه‌ی سامانه‌ی S3 در بخش ۱۲ ↗ نیز به‌کار می‌رود، چون factor هم یک شیء با کلاس مشخص است.

تمرین ۶

فهرستی بسازید که اطلاعات یک کتاب را نگه دارد: عنوان، نویسنده، و سال انتشار. سپس یک متغیر دسته‌ای مرتب برای سطح‌های «مبتدی»، «متوسط» و «پیشرفته» بسازید و بررسی کنید آیا «متوسط» از «مبتدی» بالاتر است یا نه.

نمایش پاسخ 
book <- list(title="R Programming", author="J. Chambers", year=2016)
book$title   # "R Programming"

level <- factor("intermediate",
                 levels=c("beginner","intermediate","advanced"),
                 ordered=TRUE)
level > "beginner"   # TRUE

چون factor با ordered=TRUE ساخته شده، R ترتیب سطح‌ها را می‌شناسد و می‌تواند آن‌ها را با عملگرهای مقایسه‌ای بسنجد؛ همان رفتاری که در مثال grade بالا دیدید.

حلقه نوشته‌اید، اما شاید روش درست R نباشد حلقه‌ی for روی یک وکتور کار می‌کند، اما اصطلاحاً idiomatic نیست و معمولاً کندتر هم هست. اگر با for روی یک وکتور یا ستون پیمایش می‌کنید تا محاسبه‌ای انجام دهید، تقریباً همیشه جایگزینی بردارش‌شده یا یکی از توابع خانواده‌ی apply وجود دارد (بخش ۹).

تعریف تابع function definition

square <- function(x) {
  return(x^2)
}

# the last evaluated expression is returned implicitly
add <- function(a, b=10) {
  a + b   # no explicit return needed
}

add(5)        # 15 -- b used its default value
add(5, 2)     # 7
add(b=1, a=2) # named arguments -- order doesn't matter
تمرین ۸ — پایان سطح کاربردی

یک قاب داده با سه ستون (name، age، score) برای ده نفر بسازید. تابعی بنویسید که یک وکتور عددی بگیرد و بگوید میانگین آن بالاتر از ۱۸ است یا نه. سپس با استفاده از ایندکس‌گذاری منطقی، فقط ردیف‌هایی را نگه دارید که نمره‌شان از میانگین کل بالاتر است.

نمایش پاسخ 
df <- data.frame(
  name  = c("A","B","C","D","E","F","G","H","I","J"),
  age   = c(17,22,19,30,16,24,28,20,15,33),
  score = c(14,18,12,19,10,16,17,13,9,20)
)

is_above_18 <- function(x) mean(x) > 18

is_above_18(df$age)    # TRUE

12برنامه‌نویسی شیءگراS3 & S4

زبان R چند سامانه‌ی شیءگرایی دارد. دو سامانه‌ی رایج S3 و S4 نام دارند. S3 ساده و غیررسمی است؛ S4 رسمی‌تر است و اعتبارسنجی نوع را نیز انجام می‌دهد.

سامانه‌ی S3 informal OOP

# a constructor function returning a list with a class attribute
new_animal <- function(name, sound) {
  obj <- list(name = name, sound = sound)
  class(obj) <- "animal"
  obj
}

# a generic function and its method for class "animal"
speak <- function(x) UseMethod("speak")
speak.animal <- function(x) {
  cat(x$name, "says", x$sound, "\n")
}

cat_obj <- new_animal("Cat", "Meow")
speak(cat_obj)   # Cat says Meow

سامانه‌ی S4 formal OOP

setClass("Animal", representation(
  name = "character",
  sound = "character"
))

setGeneric("speak", function(x) standardGeneric("speak"))
setMethod("speak", "Animal", function(x) {
  cat(x@name, "says", x@sound, "\n")
})

dog <- new("Animal", name="Dog", sound="Woof")
speak(dog)
کدام سامانه را انتخاب کنیم برای بیشتر کارهای تحلیل داده، S3 کافی و رایج‌تر است. اگر در حال نوشتن یک بسته‌ی رسمی هستید که به اعتبارسنجی دقیق ساختار نیاز دارد، S4 گزینه‌ی مناسب‌تری است. یک سامانه‌ی سوم به نام R6 نیز وجود دارد که شیء آن قابل تغییر (mutable) است و برای برنامه‌نویسانی که از زبان‌های شیءگرای کلاسیک می‌آیند، آشناتر به‌نظر می‌رسد.

13مدیریت خطا و اشکال‌زداییerror handling & debugging

تابع safe_divide در ادامه، همان ساختار تابع ساده‌ای است که در بخش ۸ ↗ آموختید، با این تفاوت که اکنون یک شرط خطا به آن اضافه شده است.

صدور و دریافت خطا condition system

safe_divide <- function(a, b) {
  if (b == 0) {
    stop("division by zero is not allowed")
  }
  a / b
}

# tryCatch intercepts errors, warnings and messages
result <- tryCatch({
  safe_divide(10, 0)
}, error = function(e) {
  cat("caught an error:", conditionMessage(e), "\n")
  NA
})
تابعکاربرد
stop()توقف اجرا و صدور یک خطا
warning()صدور هشدار بدون توقف اجرا
tryCatch()گرفتن خطا، هشدار یا پیام و واکنش کنترل‌شده
try()نسخه‌ی ساده‌تر، فقط برای جلوگیری از توقف برنامه
stopifnot()بررسی یک شرط؛ در صورت نادرست بودن، خطا صادر می‌شود

ابزارهای اشکال‌زدایی debugging tools

# pause execution at the start of a function, inspect variables
debug(my_function)
my_function(10)
undebug(my_function)

# insert a breakpoint anywhere in the code
browser()

# print the full call stack after a crash
traceback()
چرا نادیده گرفتن خطا خطرناک است استفاده از try() بدون بررسی نتیجه، می‌تواند خطایی را که باید دیده شود، پنهان کند. همیشه خروجی try() یا tryCatch() را بررسی کنید و مطمئن شوید که برنامه با یک مقدار نامعتبر به کار خود ادامه نمی‌دهد.
تمرین ۱۳

تابعی به نام safe_sqrt بنویسید که جذر یک عدد را حساب می‌کند، اما اگر عدد منفی بود، به‌جای خطا، پیام هشدار بدهد و NA برگرداند.

نمایش پاسخ 
safe_sqrt <- function(x) {
  tryCatch({
    if (x < 0) stop("negative input")
    sqrt(x)
  }, error = function(e) {
    warning("returned NA: ", conditionMessage(e))
    NA
  })
}

safe_sqrt(-4)   # NA, with a warning printed

این دقیقاً همان الگوی safe_divide در این بخش است، با این تفاوت که اینجا خطای گرفته‌شده در بلوک error به یک هشدار تبدیل می‌شود، نه سکوت کامل؛ این رفتار با هشدار بالا درباره‌ی خطر نادیده‌گرفتن خطا هم‌خوانی دارد.
