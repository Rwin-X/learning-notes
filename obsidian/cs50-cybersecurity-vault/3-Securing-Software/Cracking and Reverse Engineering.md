# Cracking and Reverse Engineering

**Reverse engineering**: analyzing compiled software (without source
code) to understand how it works — disassembling or decompiling binaries,
tracing execution, examining behavior.

**Cracking**: using reverse engineering (often) to remove restrictions
from software — licensing checks, DRM — or, in a security-research
context, to find exploitable vulnerabilities such as
[[Buffer Overflow and Stack Overflow|buffer overflows]].

Legitimate uses: security researchers reverse-engineering malware
([[Malware Analysis]]) to understand and defend against it, or
researchers finding vulnerabilities to responsibly disclose (connecting
to [[Bug Bounty]] and [[Common Vulnerabilities and Exposures CVE]]).
Same skill set, very different intent and legality depending on
authorization — same distinction as [[Penetration Testing]] versus
unauthorized intrusion.
